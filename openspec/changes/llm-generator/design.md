## Context

ADR-0003 把判定口径换成了声明级，ADR-0005 定死了模型接入形态：不做网关，规则引擎与模型做成同一个 `ResumeGenerator` 接口的两个实现，接口后面做生成日志、成本护栏、超时与重试、同输入缓存。

这一段要做的是那条流水线本身：**模型的输出不被信任**。模型产出先过事实账本，不合格的要点回退为规则引擎的产出；模型不可用时整版回落规则产出，功能不中断。

## Goals / Non-Goals

**Goals**：模型参与生成正文；每一条模型写的断言都能指回底稿里的事实；模型不可用时用户照样拿到一份能投的简历；每次生成可审计、可算钱、可拦住。

**Non-Goals**：不做模型网关、不做多供应商路由（ADR-0005 §1）；不追生成质量（那是灰度对比那一段的事）；不做每日次数与成本上限、同输入缓存（下一段）。

## Decisions

### D1. 端口在共享包，模型传输由服务端注入

共享包新增 `ResumeGenerator` 端口；模型调用要带密钥，而密钥不能进浏览器包，所以**传输实现放在服务端**，共享包只认一个函数端口：

```ts
export type ChatCompletion = (request: ChatCompletionRequest) => Promise<ChatCompletionResponse>
```

共享包组装 `llm` 实现时，服务端把实现了 OpenAI 格式的 `chat` 传进来。

**理由**：这是「密钥不进浏览器包」的结构保证，不是约定——前端 bundle 里根本没有能读到密钥的代码。

### D2. `rules` 实现零成本复用现有代码

`ResumeGenerator.generate` 的签名与现有 `generateVersion` 一致。`rules` 实现就是包一层。

**理由**：回退底稿必须与规则产出**逐字一致**（验收项 A4.2）。共用一份代码才谈得上「一致」。

### D3. 引用用子句序号，不让模型抄 factId

模型看到每个要点的**编号子句**，输出 `{"key": "bullet-1", "clauses": [1, 2], "text": "..."}`。引擎把序号映射回 factId。

**理由**：factId 是 16 位哈希，模型抄错一位就查不出依据——而查不出依据就等于没引用。序号短、且必须来自给定列表，抄错的概率低得多；真抄错了，引擎按「引用不存在」判不可信。

### D4. 模型只改写，不增删要点

模型与规则产出的要点**一一对应**：模型可以引用一条要点的多个子句并合成一句话，但不能让要点变多、变少或换顺序。

**理由**：结构（分区、条目、顺序、删减、覆盖）决定 diff 与覆盖率，交给模型会让整条链路失控——模型漏一条要点，覆盖率就悄悄变了。模型的价值在措辞，不在取舍。

取舍留给规则引擎：JD 要求没覆盖上，本来就是规则引擎算出来的。

### D5. 回退目标是规则产出，不是源句原文

模型那条要点不可信时，换成**规则引擎对同一条要点的产出**（也就是规则引擎已经写好的那句），不是底稿原句。

**理由**：ADR-0003 §5。规则产出本身是合法的（它只重排已有字符），回退到它比回退到原句更整齐——原句可能带项目符号、多余空白。

### D6. 两层降级

| 情况 | 处置 |
| --- | --- |
| 模型整体不可用（超时、拒答、返回坏 JSON、没有配供应商） | 整版用规则产出，`generator: 'rules'`、`degraded: true` |
| 模型整体可用，但某条要点不可信 | 那条要点换成规则产出，`reverted` 加一 |

`degraded` 的含义是「这次生成没有完全由模型产出」——两种情况都为真。界面按 `generator` 与 `reverted` 区分文案。

**理由**：用户要的是一份能投的简历。模型不可用不是错误，是降级（ADR-0005 §3）。

### D7. 提示词要短，且把「不许编造」写成可执行的约束

提示词给出：JD 的要求条目、每条要点的编号子句、规则产出那句作为起点。要点只有三句：只重组不新增、数字与专名一字不改、职责动词不得变强。

**理由**：模型会编造的正是数字与职责强度——这两条直接对应 R1 与 R4。提示词把它们写死，比让模型「注意不要编造」有用得多。

### D8. 温度 0，单次 token 上限可配

`temperature: 0`，`max_tokens` 默认 2000，由 `LLM_MAX_TOKENS` 覆盖。

**理由**：温度 0 让同一份输入的输出尽量稳定——不能保证逐字一致（T4.8 要写明），但能减少无谓的差异。token 上限是成本护栏的第一道闸。

### D9. 生成日志只存引用与模型的输出

`generations` 表记：账号、底稿引用（`draftId` + `revision`）、JD 的哈希、模型 id、提示词版本、参数、token 数、校验结论、**模型的原始输出**。

**不存简历正文**——输入用引用。但模型的输出要存：不然「审计」无从谈起（ADR-0005 §5）。

### D10. 模型的输出要过禁用词检查

模型的输出进正文之前要过 `assertCleanOutput`（禁用词：面试、八股、题目等）。这条对规则引擎产出也是同样的要求。

**理由**：模型比规则引擎更容易写出「面试」「八股」这类词——它是在训练数据里见过这些词的。

## Risks / Trade-offs

**[模型的改写会被大面积回退]** —— 这是**预期内**的：R5 划定了模型的职责边界（换词归规则引擎）。回退率是灰度对比那一段的主要指标（超过 30% 就回去调提示词与参数）。

**[提示词注入]** —— JD 是用户贴进来的，可能包含「忽略以上要求」这类文字。缓解：JD 只作为「要覆盖什么」的输入给出，判定与回退不依赖模型是否听话；模型输出的一切都要过账本。

**[模型供应商的条款会变]** —— 数据留存与是否用于训练这两条上线前要核对，写进隐私结论（ADR-0005 §4）。

**[共享包里的生成器要能在浏览器里跑]** —— 它不碰密钥、不读文件，`fetch` 也不直接用（传输是注入的端口），所以浏览器构建不会挂。

## Migration Plan

- `generations` 表要加一条迁移。
- 版本 payload 是 jsonb，`integrity` 的新字段与 `trace` 不需要迁移。
- 没配供应商时，生成路径与现在逐字一致——回滚只需把配置去掉。

## Open Questions

- 每日生成次数与成本上限、同输入缓存：下一段做。两者都要计数与存储，这一段先把 `generations` 表铺好。
- 灰度对比基线（固定一组「底稿 + JD」样本，两个引擎各跑 N 次）：下一段做，需要先有可切换的引擎。
