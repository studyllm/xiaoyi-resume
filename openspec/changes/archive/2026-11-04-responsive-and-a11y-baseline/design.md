## Context

产品目前只有桌面宽度这一种形态：应用侧栏固定 200px，纸面固定 210mm 宽，批注栏 320px。窄屏上三块加起来把纸面挤到溢出，而 1280 与 1024 宽的机器很常见。

无障碍方面：图标按钮有的带 `aria-label`、有的没有；动效没有 `prefers-reduced-motion` 兜底；纸面是整页主要内容，却没有向读屏软件播报状态的区域。

约束：

- 纸面用 mm 表达物理尺寸，**打印稿必须与预览一致**（`CLAUDE.md` §5.8）。缩放只能发生在屏幕显示这一侧。
- 视觉语言已固化（`CLAUDE.md` §4），本阶段不重新设计。
- `flows.spec.ts` 已经是规范守卫，样式扫描覆盖全量样式文件。
- 范围只有「不破版 + 明确降级」，不做移动端专属布局。

## Goals / Non-Goals

**Goals:**

- 四档断点，每档行为确定。
- 窄屏不破版、不溢出。
- 屏幕过小时给明确降级提示，而不是让用户面对一个挤扁的界面。
- 四条无障碍基线落地。

**Non-Goals:**

- 不做移动端专属布局、不做触摸手势。
- 不做完整 WCAG 审计（列入 v1.1）。
- 不改引擎、不改数据模型。
- 不改纸面版式与打印输出。

## Decisions

### D1. 断点与档位是纯函数

`domain/breakpoints.ts` 只做「宽度 → 档位」的映射，不碰 DOM。视图不自己比数字。

**理由**：断点散落在各处时，改一个分界要翻遍全仓库；而且档位判定要能单测。纯函数是唯一能测的形式。

### D2. 纸面用 `zoom` 缩放，不用 `transform: scale()`

`transform: scale()` 不改变布局盒——缩放后的纸面在容器里仍占 210mm 的宽度，容器照样溢出，除非再写一套「缩放后宽高」的 JS 补偿。`zoom` 会重排：元素连同文字一起按比例缩小，容器的宽高跟着变，没有溢出也没有多余留白。

**理由**：我们要的就是「等比缩放」——文字变小、行不变、列不变。`zoom` 恰好是这个语义。

**代价**：`zoom` 不是 W3C 标准。Chrome 与 Safari 一直支持，Firefox 自 126（2024-05）起支持。原型面向现代浏览器，这个代价可以接受。**打印样式里必须把它复位成 1**——否则打印稿会被缩放。

**备选**：`transform: scale()` + `ResizeObserver` 测高补偿。能避免非标准属性，但要引入一个常驻的观察器和一套高度补偿逻辑，为一个原型不值得。

### D3. 缩放比例按容器实测宽度算，不按视口宽度推

纸面的可用宽度 = 视口 − 应用侧栏 − 批注栏 − 页面留白。这几项随状态变（批注栏在 1360 以下会收成图标条），从视口宽度推算要复制一套布局计算。直接量纸面所在容器的 `clientWidth` 更准，也更少代码。

**下限 0.7**：低于这个比例正文已经小到读不了，与其给一个看不清的纸面，不如让内容横向滚动。

### D4. 侧栏抽屉用覆盖层，不做推挤

抽屉打开时覆盖在内容之上，底下压一层遮罩。推挤式（把内容往右挤）会让正在看的纸面跳一下位置，编辑中的用户会失去上下文。

### D5. <768 不渲染工作台，改渲染降级提示

屏幕小于 768px 时，纸面缩到 0.7 也就是 550px 宽的正文——在手机上读简历是可行的，但**编辑**一份简历不可行。与其给一个半残的编辑器，不如明确告诉用户换个屏幕。

**降级提示里要说清为什么**，不然用户会以为页面坏了。

### D6. 焦点环常显，但不覆盖组件库焦点样式

`CLAUDE.md` §5.6 要求「键盘焦点必须始终可见」。做法是给 `:focus-visible` 一个统一的焦点环，而不是把组件库的 `--el-*` 焦点变量清零。`:focus-visible` 只在键盘操作时出现，鼠标点击不显示——这是浏览器的既定行为，也符合「不因为鼠标点击就抹掉焦点环」的要求（鼠标点击本来就不该显示焦点环）。

### D7. 状态播报用 `aria-live="polite"`

纸面区域是页面主体，它的内容变化（保存成功、诊断条数）用 `aria-live="polite"` 播报。`assertive` 会打断读屏软件正在读的内容，对「已保存」这种不需要立刻打断的消息不合适。

## Risks / Trade-offs

**[`zoom` 在打印时把纸面缩了]** → 打印样式里显式 `zoom: 1`，并加一条守卫断言打印样式里有这一行。

**[Firefox 126 之前不支持 `zoom`]** → 记录在 `docs/responsive-breakpoints.md` 的已知限制里；那种浏览器上纸面会横向溢出，不至于白屏。

**[抽屉打开时内容区不滚动]** → 抽屉本身 `overflow-y: auto`，长菜单在抽屉里能滚。

**[测量容器宽度在首帧拿不到]** → 初始比例取 1，`ResizeObserver` 首次回调后修正。首帧可能有一帧的溢出，不影响使用。

**[`aria-label` 守卫误伤有文字的按钮]** → 只对「标签里只有图标、没有可见文字」的按钮要求 `aria-label`。判定靠模板结构，不靠 CSS。

## Migration Plan

无数据迁移。回滚就是把分支合回去。

## Open Questions

- 纸面缩放的最低比例 0.7 是拍的，没有实测过「在 550px 宽的纸上读正文」的舒适度。v1.0 上线后按真实反馈调。
- 抽屉唤出按钮的图标用 Element Plus 的 `Expand`/`Fold`，还是自绘。倾向前者。
