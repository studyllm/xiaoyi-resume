## Context

刷新 `/jd` 会被守卫送回导入页。守卫判「有没有底稿」的时候，草稿还在从服务端读的路上。

## Goals / Non-Goals

**Goals:**

- 有底稿时，刷新那些需要底稿的页面能进去。

**Non-Goals:**

- 不改草稿的加载逻辑。
- 不改「真没有底稿」时的行为（送回导入页 + 提示）。

## Decisions

### D1. 守卫等这次重载结束

草稿 store 已经把在飞的重载记在 `restoring` 里（保存前要等它，否则带的是旧账号的修订号）。守卫直接用这个承诺：等它结束，再看有没有底稿。

不用「再读一次」——那会多发一次请求，也可能在等的过程中被别的重载顶掉。

### D2. 等的是「这次」，不是「有没有在飞」

`whenRestored()` 在没有重载在飞时立刻 resolve ✓——客户端跳转（草稿已在内存里）不受影响 ✓。

## 验证方式

- `frontend/src/router/index.spec.ts`：草稿延迟返回时，守卫不会误判「没有底稿」，路由停在 /jd。
  - **这条用例在修复前是红的**：路由被改成 /import ✓。
- 手工（真实浏览器）：刷新 /jd → 停在 JD 页 ✓（修复前被送回导入页 ✓）。
- 仓库根 `npm run verify` 全绿。
