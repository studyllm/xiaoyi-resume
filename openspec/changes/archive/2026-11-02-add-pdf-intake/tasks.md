## 2. 提取模块 `frontend/src/engines/pdfText.ts`

- [x] 2.1 文件校验：读文件头 5 字节判定 `%PDF-`（不信浏览器给的 MIME）；大小上限 10MB、页数上限 50 页；各自一句可执行文案
- [x] 2.2 打开文档并逐页取 `getTextContent()`，把片段按 y 聚成视觉行（容差取片段高度一半，最少 2pt），行内按 x 排序
- [x] 2.3 行内拼接：空白片段贡献一个空格、有内容的片段直接接上；**整行输出为一行，不因间距大而拆行**（design.md 决策 3）
- [x] 2.4 拼接完成后对整段文字做一次 NFKC 归一化，把兼容字形还原成常用字（design.md 决策 5）——不做这一步，Chrome 等生成器导出的 PDF 里「工作经历」会变成「⼯作经历」，分区标题全部认不出来
- [x] 2.5 质量三态判定：`none`（全文去空白后为空）/ `sparse`（平均每页字符数 < 80）/ `text-layer`（其余）。阈值写成具名常量并注明依据（design.md 决策 6）
- [x] 2.6 错误分类：口令保护、文件损坏、其它异常各自分类，产出各自的用户可见文案；文案里不得出现题目类词汇
- [x] 2.7 返回结构固定为 `{ text, pageCount, quality, warnings }`，`quality` 取值域预留 `'ocr'`（design.md 决策 7）
- [x] 2.8 单测：文字层完整 / 无文字层 / 文字很少三档各自判定正确；条目头与日期在同一行且没被拆开；兼容字形归一化后是常用字；非 PDF 字节头被拒；超限被拒；口令与损坏错误分类正确
- [x] 2.9 多栏 PDF 不做特殊处理（design.md 决策 4）——按视觉顺序输出即可，**不要加任何按 x 位置分栏的逻辑**：右对齐的条目头与真正的分栏在几何上无法区分，误判会把单栏简历重排
- [x] 2.10 单测跑 `npm run type-check` 零错误；`frontend/src/engines/pdfText.ts` 不出现在 `ResumeEngines` 接口上
