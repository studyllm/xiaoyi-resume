## Why

编辑模式下，「＋新增一条要点」和「＋新增一段教育经历 / 一段工作经历 / 一个项目」用的是同一个样式（`.paper-add`），实测：

| 元素 | 相对版心左边界 | 宽度 |
|---|---|---|
| 条目头（清华大学 …） | 0 | — |
| 要点正文 | +34px（9mm） | — |
| **「＋ 新增一条要点」** | **−0.3px** | **680 通栏** |
| **「＋ 新增一段教育经历」** | **−0.3px** | **680 通栏** |

纸上一共 9 个「＋新增」按钮，**全部**在版心左边缘、通栏、同字号、同虚线。所以「在清华这段经历下面加一条要点」和「在教育背景这个分区下面加一段经历」看起来是同一层的事——产品负责人指出这两个显示得平级了。

纸面本来就有三级缩进（分区 0 → 条目 0 → 要点 9mm），新增入口没跟着走。

## What Changes

条目里的「＋ 新增一条要点」缩进到 9mm，跟要点正文对齐；分区末尾的「＋ 新增一段…」保持在版心左边缘。条目级那条的虚线也跟着从 9mm 开始画，比分区级那条短一截。

```
· 主修数据结构、操作系统与数据库系统，GPA 3.7/4.0   删除
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
  ＋ 新增一条要点              ← 缩进到跟要点正文对齐
┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
＋ 新增一段教育经历            ← 保持在版心左边缘
```

规则一句话说得清：**按钮在哪一层，就摆在哪一层的缩进上**。专业技能分区没有"条目"这一层，它那个「＋ 新增一条技能」归分区级，不缩进。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `resume-draft`: 「可新增要点、条目与技能行」补上「新增入口按层级缩进」

## Impact

**代码**

- `frontend/src/components/ResumeEditor.vue`：条目里的「＋ 新增一条要点」加一个层级修饰类
- `frontend/src/components/resume-editor.css`：嵌套的那个入口缩进到 9mm，宽度跟着减

**不受影响**

- 不改两个按钮的措辞、字号、颜色、虚线样式
- 不改要点本身的缩进
- 不动专业技能分区的结构
- 不新增依赖
