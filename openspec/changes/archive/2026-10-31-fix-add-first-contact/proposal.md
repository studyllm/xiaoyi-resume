## Why

简历抬头里的联系方式，用户一个都没有的时候，「新增联系方式」那个按钮根本不渲染。

`ResumePreview.vue` 里联系方式那一行的判定是：

```html
<p v-if="profile.contacts.length > 0" class="paper-contacts">
  <slot name="profile-contacts" :profile="profile">…</slot>
</p>
```

没有联系方式 → 整块不渲染 → 插槽里的「＋ 新增联系方式」按钮也就没了 → 用户没法加第一条。粘贴进来的简历常常不带联系方式（解析器只在正文头部认得出姓名与联系方式时才提取），于是这条路直接堵死。

这是上一轮补测试时撞出来的：测「联系方式可以新增与删除」只能先从 store 里塞一条进去，才点得到那个按钮。

## What Changes

联系方式那一行在**编辑模式**下始终渲染，跟纸面上其它字段一个规矩（条目头也是 `item.org || editable`：编辑时空条目也得有输入框可填）。

```
现在（没有联系方式时）        改后（编辑模式）
┌──────────────────┐        ┌──────────────────┐
│ 张三              │        │ 张三              │
│ 前端工程师 · 6 年经验 │        │ 前端工程师 · 6 年经验 │
│                  │        │ ＋ 新增联系方式    │
│ 教育背景 …        │        │ 教育背景 …        │
└──────────────────┘        └──────────────────┘
```

预览模式的判定不变：没有联系方式就不显示这一行，纸面干净。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `resume-draft`: 「底稿以结构化内容保存并可直接编辑」补上「没有联系方式时也能新增第一条」

## Impact

**代码**

- `frontend/src/components/ResumePreview.vue`：联系方式那一行的判定加上 `|| editable`

**不受影响**

- 不改预览模式：没有联系方式时那一行仍然不渲染
- 不改联系方式的数据结构与保存方式
- 不影响编辑区宽度（那一行本来就在抬头里）
- 不新增依赖
