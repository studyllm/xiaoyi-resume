## Why

上一轮把「我的简历」改成纸面呈现后，编辑页**无条件**同时渲染了三样东西：可编辑的控件、批注栏、以及纸上按严重度着色的高亮。结果是用户一进「我的简历」，看到的是一张既是表单、又带彩色标注、还挤着一条批注栏的纸——三套信息叠在一起，谁都读不清。

用户的原话是"整个页面看起来有点乱"。这不是配色或间距的问题，是**一屏里同时承担了两种互相冲突的意图**：

```
意图一：看一眼我的简历长什么样      → 要干净
意图二：带着诊断建议改这份简历      → 要批注
```

两件事挤在同一屏、同一套控件上，就必然乱。

## What Changes

**「我的简历」拆成预览与编辑两种模式**

```
预览模式（默认）                      编辑模式
┌────────┬──────────────┐            ┌────────┬──────────────┬──────────┐
│ 侧栏    │              │            │ 侧栏    │              │ 批注      │
│ 导航    │   纸（只读）  │            │ 导航    │  纸（可编辑）   │ ▓ 缺可衡量 │
│ ──────  │              │            │ ──────  │              │   建议：…  │
│ 分区目录 │              │            │ 分区目录 │              │ ▓ 表述空泛  │
│  教育 1 │              │            │  教育 1 │              │          │
│  工作 2 │              │            │  工作 2 │              │          │
└────────┴──────────────┘            └────────┴──────────────┴──────────┘
  无批注栏 · 纸上无高亮                有批注栏 · 纸上按严重度高亮
```

- **每次进入「我的简历」默认预览模式**：纸只读、没有批注栏、纸上没有任何高亮
- **切到编辑模式**才出现批注栏，纸上的问题片段与标题才按严重度着色，同时内容可就地修改
- **预览模式下页头给一条轻提示**（如「4 条诊断意见 · 去诊断」），点进去是诊断页——纸保持干净，但用户不会误以为这份简历没问题
- **批注栏为空时给一个「去诊断」按钮**：编辑模式不自动跑诊断，但空批注栏要给出下一步

**从诊断页「去修改」直达编辑模式**

```
现在：诊断页「去修改」→ 定位 → push('/draft')
      → 编辑页永远是编辑态、永远带批注栏

改后：诊断页「去修改」→ 请求编辑模式 + 定位 + 展开该批注 → push('/draft')
      → 编辑页以预览态进入，被这次请求覆盖为编辑态
```

**范围边界**

- 「简历诊断」页保持独立存在：它是审阅工作台（有筛选、有「已处理 3/6」进度、只读），编辑模式是编辑工作台（可改）。两者视觉相近但意图不同，靠批注栏顶部有没有筛选与进度来区分
- 不改任何诊断规则、批注内容与版本能力
- 不改数据模型与存储键
- 预览与编辑模式的切换不持久化——每次进入「我的简历」都是预览

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `resume-draft`: 「底稿以结构化内容保存并可直接编辑」增加预览与编辑两种模式，预览为默认
- `resume-comment-anchoring`: 「编辑时批注与句子同屏」限定为编辑模式，预览模式不显示批注
- `draft-diagnosis`: 「意见落到具体句子并说明问题」中，从意见跳转的动作改为进入编辑模式

## Impact

**代码**

- 新增 `frontend/src/components/PaperField.vue`：文本与输入两种形态的可编辑控件，模式差异收敛到这一个组件
- `frontend/src/views/DraftView.vue`：模式状态、模式切换控件、按模式决定是否渲染批注栏与高亮
- `frontend/src/views/DiagnosisView.vue`：「去修改」改为请求编辑模式
- `frontend/src/stores/ui.ts`：新增一次性编辑模式请求
- `frontend/src/components/CommentSidebar.vue`：空状态给出「去诊断」入口

**顺带**

- 抽出 `PaperField`，把「文本 or 输入」的差异收敛到一个组件里；`DraftView.vue` 的行数没有因此下降（两态分支仍在十个插槽中），进一步拆分另开变更

**不受影响**

- 不新增依赖，不产生网络请求
- 引擎层、领域模型、持久化结构完全不动
