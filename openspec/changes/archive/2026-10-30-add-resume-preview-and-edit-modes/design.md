## Context

上一轮把编辑页改成纸面呈现后，编辑页同时渲染了三层信息：

```
ResumePreview 的可编辑插槽   ← 每个字段一个输入框
:highlights                 ← 纸上按严重度着色的高亮
CommentSidebar              ← 右侧批注栏
```

三者一起出现，用户看到的不是一份简历，而是一张"既是表单、又带彩色标注、还挤着侧栏"的纸。

根因是**一屏承担了两种互相冲突的意图**：看一眼（要干净）与 带着建议改（要批注）。上一轮把两种意图做成了同一个页面的同一个状态。

现在的形态对比：

```
简历诊断页      纸（只读）+ 批注栏 + 筛选 + 已处理进度   ← 审阅工作台
我的简历        纸（可编辑）+ 批注栏 + 高亮             ← 编辑工作台，但也是审阅工作台
```

两个页面几乎一样，且"我的简历"默认就把审阅层摊开了。

## Goals / Non-Goals

**Goals:**

- 「我的简历」默认是预览模式：纸只读、无批注栏、纸上无高亮
- 切到编辑模式才出现批注栏与高亮，并可就地修改
- 从诊断页「去修改」直达编辑模式并定位到那条批注
- 预览模式下用一条页头轻提示告知"有 N 条诊断意见"，但纸保持干净
- 批注栏为空时给出「去诊断」入口
- 顺带把 `DraftView.vue` 拆小

**Non-Goals:**

- 不做「简历诊断」页与编辑模式的合并（已定：两个都保留）
- 编辑模式**不自动跑诊断**（已定：空批注栏给「去诊断」按钮）
- 不改诊断规则、批注内容、版本与导出能力
- 不做模式持久化——每次进入「我的简历」都是预览
- 不改数据模型与存储键

## Decisions

### D1 模式是页面的本地状态，不持久化

「我的简历」每次进入都是预览。这条来自用户的原话「刚进入菜单默认到方式」。

模式本身放在组件本地 `ref`，只有一种情况例外：诊断页请求进入编辑模式。这个请求通过 uiStore 传递，且**是一次性的**——编辑页挂载时消费掉随即清空，否则模式会粘住。

```
uiStore.requestEditMode(issue?)   ← 诊断页「去修改」调用
        ↓
编辑页 onMounted：读到请求 → mode = 'edit' → 展开该批注 → 清空请求
        ↓ 没有请求
             mode = 'preview'
```

### D2 预览模式就是「不传插槽、不传高亮」

`ResumePreview` 本来就支持只读渲染——版本详情页的「简历预览」页签就是这个形态。所以两态的差异只是传不传插槽与 highlights，不需要两套组件。

```
预览：<ResumePreview :sections :profile />
编辑：<ResumePreview :sections :profile :highlights> …十个插槽… </ResumePreview>
```

### D3 抽 `PaperField`，把模式差异收敛到一个组件

十个插槽里有四个是「文本 or 输入框」二选一。若不抽组件，两种模式各写一遍就翻倍。抽出来之后每个插槽只有一行：

```vue
<template #item-org="{ section, item }">
  <PaperField
    :editable="editable"
    :value="item.org"
    placeholder="公司或机构"
    @update="(v) => draftStore.updateItemMeta(section.id, item.id, { org: v })"
  />
</template>
```

`PaperField` 内部 `editable ? el-input : span`。**模式切换的复杂度全部落在这一个组件里**，其余插槽只管传值。

顺带解决上一轮遗留的问题：`DraftView.vue` 现在 652 行（全项目最大），抽完降到 400 行以内。

剩下三个插槽（联系方式、日期、要点正文）本身形态更复杂，各自用一个 `v-if` 分支即可，不进 `PaperField`。

### D4 批注栏在编辑模式才渲染

预览模式下整个 `CommentSidebar` 不渲染——不是"渲染了但藏起来"，因为空的侧栏和纸上的高亮一样会干扰阅读。

纸上高亮同理：`highlights` 只在编辑模式传。

### D5 预览模式给一条页头轻提示，但不碰纸

完全不提诊断，用户会以为"我的简历没问题"，而意见藏在另一个页面。

提示放在页头而不是纸上——纸一被弄脏，"预览"就失去意义了。

**措辞要轻。** 上一轮刚把全宽的黄色警告条降噪成一条细线，如果这里又用 `el-alert` 或警告色，等于把刚收回去的噪音又请回来。所以：

```
页头：[ 预览 | 编辑 ]      4 条诊断意见 · 去诊断 →
                            ↑ 计数与文字都是弱化灰
                                          ↑ 只有这个链接用主色
```

不用图标、不用标签、不用警告色、不用背景块。计数说明"有多少"，链接说明"能去哪"，其余全部退到背景里。

### D6 编辑模式不自动跑诊断，空批注栏给「去诊断」按钮

自动跑诊断有两个问题：一是隐式行为，二是会清掉用户已经标记的「已处理」。所以不自动跑。

但编辑模式的价值就是"带着建议改"，没有建议的编辑模式等于没进。所以空批注栏要明确给出下一步：

```
┌ 批注栏（空） ────────┐
│  还没有诊断结果        │
│  [ 去诊断 ]            │
└──────────────────────┘
```

### D7 诊断页与编辑模式并存，靠批注栏顶部的差异区分

两者视觉相近，但意图不同：

```
简历诊断页的批注栏         编辑模式的批注栏
  批注 6   待处理 4          批注 6
  [严重度▾][类别▾]           （没有筛选与进度）
  ▓ 缺可衡量的结果 · 已处理    ▓ 缺可衡量的结果
```

诊断页是**审阅工作台**（处理意见、标记已处理、按严重度筛），编辑模式是**编辑工作台**（边改边看）。前者只读，后者可改。

### D8 模式切换时纸会横向跳动

预览时纸居中在宽区域，编辑时纸居中在窄区域（右侧让出 320px 给批注栏），左边缘相差约 160px。

两个选择：预览居中 / 编辑靠左（纸全程不动，只右边长出批注栏）；或者两态都居中、接受一次跳动。

**取后者：两态都居中，接受一次跳动。** 切换是用户主动动作，纸的位置变化可预期；而"预览时纸居中"更好看。宽度差异过大时，纸允许横向滚动。

## Risks / Trade-offs

**[用户找不到编辑模式]** → 模式切换控件放在页头，与「修订号」并排，用分段控件的形态（预览 / 编辑），不用图标

**[编辑模式里纸与批注栏仍显得拥挤]** → 1440px 下 200 + 794 + 320 = 1314 可容纳；窄于 1360px 时批注栏折叠成图标条（机制已存在）

**[从诊断页跳来时用户以为还在诊断页]** → 跳转后编辑页顶部提示「已从诊断定位到该条意见」，并展开对应批注，视觉上能看出已进入编辑态

**[预览模式与版本详情页的「简历预览」看起来一样]** → 是的，两者都是只读纸。但语义不同：一个是"我的简历现在长这样"，一个是"这一版投出去长这样"。版本详情页那份不可编辑，预览模式这份可切编辑

**[编辑模式切回预览时，未保存的修改怎么办]** → 修改是即时的（每次输入即落库并递增修订号），所以不存在"未保存"。切回预览只是收起控件，数据已在库里

## Migration Plan

1. 新增 `PaperField.vue`（文本 / 输入两种形态）
2. `uiStore` 增加一次性编辑模式请求
3. 编辑页：模式状态、页头切换控件与轻提示、按模式决定批注栏与高亮的渲染
4. 诊断页：「去修改」改为请求编辑模式
5. `CommentSidebar`：空状态给出「去诊断」
6. 验证：预览态无批注无高亮、编辑态批注可见、从诊断跳转直达编辑并展开、窄屏折叠仍可用

**回滚**：改动集中在编辑页与两个新增件，无数据迁移。

## Open Questions

本设计无遗留开放问题。以下六项已定案，记录于此以免后续被重新提起：

| 问题 | 结论 | 落在 |
|---|---|---|
| 诊断页是否与编辑模式合并 | 不合并，两个都保留 | D7 |
| 进编辑模式是否自动跑诊断 | 不自动，空批注栏给「去诊断」 | D6 |
| 预览模式是否提示有诊断意见 | 页头一条轻提示，不碰纸 | D5 |
| 模式是否持久化 | 不持久化，每次进入都是预览 | D1 |
| 模式切换后纸的位置 | 两态都居中，接受一次跳动 | D8 |
| 页头提示的措辞 | 轻：计数与文字弱化灰，只有链接用主色 | D5 |
| 纸面的可编辑控件 | 抽 `PaperField` 收敛 | D3 |
