## Why

拿一份真实的 PDF 简历（`资深 Java 后端工程师 (12年经验).pdf`）跑一遍导入，保存时报出 11 条结构问题。逐条查下来，**没有一条是「用户简历写得不好」，全是我们自己的问题**：

| 报出的问题 | 真实原因 |
| --- | --- |
| 时间有重叠 ×2 | **假阳性**。两段经历首尾相接（`2020/09 – 2022/04` 接 `2017/09 – 2020/09`）被判成同时在干两份 |
| 没有按时间倒序 ×4 | **能自动修却报了**。解析器保留原文顺序，检查却要求倒序 |
| 缺少公司名称 / 职位 / 项目名称 ×3 | 标签只显示「未命名的条目」，用户认不出那是哪一段，无从判断是自己漏写还是解析没认出来 |

三条都是同一类毛病：**产品把「自己能修的事」当成问题抛给用户，或者把「修不了的事」说得没头没脑。**

## What Changes

- **首尾相接不算时间重叠**。简历里相邻两段经历交接在同一个月是常态，那是交接不是同时干两份；共用两个月以上才是真重叠。
- **解析完按开始时间倒序排**。结构检查本来就要求倒序，解析器却保留原文顺序——一边不排一边报。能自动修的就别报错。
- **条目既没有机构名也没有职位时，用它的第一条要点开头当标签**，不再显示「未命名的条目」。用户至少能认出那是哪一段。

这一轮只动检查与展示层，不碰条目头的切分规则（那是下一轮）。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `resume-draft`: 「按时间倒序排列」从要求用户改改成解析时排好；「没有机构名或职位」补上可辨认的标签

## Impact

**代码**

- `packages/shared/src/domain/time.ts`：`rangesOverlap` 不再把共用一个月算重叠
- `packages/shared/src/domain/time.spec.ts`：那条「首尾相接算重叠」的用例改成新语义，并补一条「共用两个月算重叠」
- `packages/shared/src/engines/parseDraft.ts`：解析完按开始时间倒序排
- `packages/shared/src/engines/structure.ts`：标签回落到第一条要点

**不受影响**

- 不改任何端点、错误码与用户文案
- 不改条目头的切分规则（机构名与职位切反、日期跨行、表格被切碎）——那是下一轮
- 不改诊断与结构标注的判定口径，只改它们引用的那一个标签
