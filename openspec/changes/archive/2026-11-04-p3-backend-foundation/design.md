## Context

P3 要把「本机 localStorage + 一个名字」换成真实账号与真实存储。计划给了 12 人日的估算、一个前端工程师兼任后端的前提，以及三条必须先冻结的接缝（F1 异步化、F5 账号标识、F9 共享包）。

这些决定互相咬合：语言定了才谈得上共享包，共享包定了才谈得上引擎放哪，引擎放哪定了才谈得上鉴权与服务端 API 的形状。

## Goals / Non-Goals

**Goals:**

- 把技术栈、鉴权模型、引擎位置三组决定写下来，每组带「什么时候重开」。
- 让 P3 的第一个任务（API 契约冻结）能直接开工，不用再回头问「用哪个框架」。
- 把「明确不做的」写下来，避免范围膨胀。

**Non-Goals:**

- 不写 API 契约本身（那是 T3.1，第一个实现变更的事）。
- 不动代码、不动生效规格。
- 不定 P4 的 LLM 适配层细节（只定「保持全 TS」这条方向）。

## Decisions

### D1. 语言由 F9 决定，不由偏好决定

服务端必须能跑 TypeScript——否则共享引擎这条约束无法满足。其余一切都跟着走：npm workspaces、Fastify、Drizzle、Postgres。

**备选**：Python（FastAPI）。LLM 生态更好，但直接复制引擎。**否掉**。

**备选**：Go / Rust。单二进制、性能好，但破 F9 且违背「前端工程师兼任」。**否掉**。

**备选**：Supabase / Firebase 等 BaaS。最快，但隐私面变成供应商的，与 F8 冲突；且 A3.2 要求后端断言账号隔离、T3.9 要求结构化日志与请求 id，都要在平台自己的观测方案里绕。**否掉**，但保留「只托管 Postgres、鉴权与 API 自建」这个中间态。

### D2. 契约写代码，不写散文

`docs/api-contract.md` 是 TypeBox schema 的说明，不是手写文档。前后端从同一份 schema 取类型，契约漂移在编译期暴露。

**理由**：计划 D1 要的是「前后端与测试有同一份契约」，A3.1 要的是「契约文件与实现的字段/错误码一致性由测试断言」。schema 即契约时，这两条都不需要额外工作量。

### D3. 数据模型用 JSONB 存简历，不拆关系表

简历与版本是树形结构（分区 → 条目 → 要点），硬拆成关系表比 JSONB 更复杂。账号隔离靠外键与查询条件。

**理由**：计划 A3.2 要求「甲账号的版本列表对乙账号不可见（后端断言，非仅前端）」——这靠的是查询条件与外键，不是表结构。

### D4. 备份必须离机，且每月演练

同机备份等于没备份。每月把备份恢复到临时容器跑一遍校验——没演练过的备份不算备份。

**理由**：这是「全部自管」这个选择的直接代价，代价要在选型时就认下来。

### D5. 观测用最轻的组合

一个 VPS 撑不起 Prometheus，还多一个要维护的组件。`/healthz` + 外部 uptime 监控 + Sentry + 每日巡检 SQL。

### D6. 引擎在服务端，mock 保留

见 ADR-0004。关键点是「同一份源码」由 npm workspaces 保证，不是靠两套实现对齐——这是 F9 想防的东西。

### D7. 邮件服务商接，但选型判据先写死

判据按重要性：送达率到中文邮箱 > SPF/DKIM/DMARC 可配 > 投递结果可查 > 数据出境说明。默认阿里云邮件推送（前提：用户主要在国内）。

**理由**：选型判据比具体品牌重要——品牌随时可换，判据不会。

## Risks / Trade-offs

**[自管数据库 + 自建邮件，两个自维护的东西叠在一起]** → 邮件投递的送达率我们控制不了，会变成客服负担。缓解：发信记录可查，界面上的「没收到验证邮件」给出明确出路（进 `docs/error-taxonomy.md` 的状态表）。

**[F9 的约束让服务端语言没有选择余地]** → 好处是「同一输入同一输出」有结构保证。代价是放弃 Python 的 LLM 生态。P4 用 TypeScript 的 Anthropic SDK 补偿；若届时不够，再单独立 ADR。

**[契约用 schema 生成，工具链耦合]** → TypeBox 的 schema 是契约的唯一来源。工具链换掉时契约要重写，但那时契约本来也要改。

**[把退役 delta 推迟到实现变更]** → 好处是规格不会先于实现打脸；代价是这两个变更之间有一段时间 `account-access` 仍写着「无密码」。**决定已经写在 ADR-0002 里了，实现变更开工时照着做即可。**

## Migration Plan

无代码改动，无数据迁移。

## Open Questions

- 邮件服务商的具体品牌：默认阿里云邮件推送，上线前确认用户地域分布后可换。
- Postgres 的具体托管形态在生产上是「同机容器」还是「同机 + 托管备份到对象存储」——前者便宜，后者抗机器故障。备份方案里两者都要，取决于机器故障时能不能接受停机。
