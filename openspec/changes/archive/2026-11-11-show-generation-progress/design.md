## Context

生成要 40-90 秒（模型改写一整版简历），界面上只有一个转圈的按钮。

## Goals / Non-Goals

**Goals:**

- 用户在等待期间知道在等什么、等了多久。
- 用户提前知道「模型调不通会回落规则引擎」。

**Non-Goals:**

- 不做假进度条。
- 不改生成的时序（还是一次同步请求）。
- 不做「中途取消」——服务端没有取消接口，这次不做。

## Decisions

### D1. 如实说「已等待 N 秒」，不做进度条

服务端是同步调用：请求发出去之后，前端拿不到任何进度信息 ✓。进度条会显示一个假的百分比 ✓ —— 那比没有更糟（用户会盯着一个不动的条 ✓）。

「已等待 N 秒」是能如实说的 ✓：它证明还在跑 ✓。

### D2. 提示放在按钮上方

生成按钮在页面最下面 ✓ —— 提示紧挨着它 ✓，用户点完就能看见 ✓。

### D3. 提前说「调不通会回落规则引擎」

降级是设计好的行为 ✓（契约 §9 ✓），但用户在等待期间不知道 ✓ —— 等到结果出来才发现「模型没用上」✓，会以为是自己操作错了 ✓。提前说 ✓。

### D4. 两种生成给不同的提示

用模型要 40-90 秒 ✓，用规则引擎几秒就好 ✓ —— 同一句「正在生成…」会让用规则引擎的人以为也慢 ✓。分开说 ✓。

## 验证方式

- `frontend/src/views/JdView.spec.ts`：等模型时界面说清在等什么、有计时；结束后提示消失 ✓
  - **这条用例在修复前是红的**（页面上没有那句提示）✓
- 手工：勾上「本次用模型」生成 → 按钮上方出现「正在等模型改写 / 已等待 N 秒」✓
- 仓库根 `npm run verify` 全绿 ✓
