## Why

两件事叠在一起。

**一、编辑模式现在只能改，不能增删。** 上一轮把编辑页从表单换成纸面时，只搬了"改"的部分——`addItem` / `addBullet` / `removeItem` / `removeBullet` 四个方法在 store 里都还在，但没有任何 UI 入口。实测编辑模式下的按钮只有「重新导入简历（覆盖）」和「新增联系方式」。用户能改字，能改抬头，但加不了一段经历、一个项目、一条技能，也删不掉任何一条。

**二、修订号是按键计数器。** 输入事件直接落库、每次都 `revision += 1`：

```
改字前：简历修订号 1
打了 7 个字后：简历修订号 8
```

"简历修订号"于是失去了意义，而版本列表与版本详情都显示它，两个版本的修订号可能差几百。

这两个其实是同一个根因：**「即时保存」没有边界**。没有边界，于是既没有撤销（改错一个字永久改掉，简历没有草稿历史），修订号也不知道该按什么计。

## What Changes

**改为显式保存**

```
draft          当前内容（编辑即改，始终在内存里，不丢字）
savedRevision  已保存的修订号 ← 只有点保存才 +1
savedSnapshot  上次保存的内容  ← 供「放弃修改」用
dirty          有未保存的修改
```

内容始终即时更新，变的只是**什么时候固化**：保存时修订号 +1 并写入本地存储。

**预览模式显示当前内容（含未保存）**。否则编辑到一半切预览，未保存的改动看不见了，用户会以为丢了。这样两个模式的差别仍然只有"能不能改 + 有没有批注"。

**生成版本与导出 PDF 前自动保存**，让版本记录的修订号与内容对得上。

**离开页面时提示未保存**（路由离开与刷新页面都要）。

**补齐纸上的新增入口**，三个层级各说各的话：

```
工作经历 ───────────────────────────────────────
  美团  前端工程师                  2021-03 - 至今
  · 主导活动平台前端架构升级，构建时间从 120s 降到 18s
  · 沉淀通用组件库，支撑 20+ 业务线接入
  ＋ 新增一条要点                    ← 条目末尾，hover 出现

  阿里巴巴  前端工程师              2019-07 - 2021-02
  · 参与商家后台管理系统开发…

  ＋ 新增一段工作经历                ← 分区末尾，hover 出现
```

| 分区 | 新增措辞 | 新增出来的东西 |
|---|---|---|
| 教育背景 | ＋ 新增一段教育经历 | 条目（学校 / 专业 / 起止年月） |
| 工作经历 | ＋ 新增一段工作经历 | 条目（公司 / 职位 / 起止年月） |
| 项目经历 | ＋ 新增一个项目 | 条目（项目名 / 起止年月） |
| 专业技能 | ＋ 新增一条技能 | 一条要点（技能区没有条目层） |

**空对象自动清理**：空要点/空条目失焦后若仍为空就移除，不在纸上留空壳；空要点的占位文案是「点此写一条要点」。

**删除要点与条目**：hover 出现，二次点击确认（不做撤销，所以删除不可逆）。

**新增的条目插在末尾**。简历是时间倒序的，新经历通常是最近的，插末尾会顺序不对——但底稿的顺序本来就是用户手工维护的，诊断的「未按时间倒序」会提醒，这条闭环是现成的。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `resume-draft`: 「底稿以结构化内容保存并可直接编辑」改为显式保存语义，并新增「可新增要点、条目与技能行」「可删除条目与要点」两条需求

## Impact

**代码**

- `frontend/src/stores/draft.ts`：拆分"改动"与"保存"，引入 `savedRevision` / `savedSnapshot` / `dirty`，移除逐字输入时的修订号递增
- `frontend/src/views/DraftView.vue`：编辑模式的保存与放弃、纸上的新增入口、删除入口、空对象清理、键盘流
- `frontend/src/components/ResumePreview.vue`：为新增与删除入口留出插槽
- `frontend/src/components/PaperField.vue`：空对象的占位提示
- `frontend/src/router/index.ts`：路由离开时的未保存提示

**顺带修掉的回归**

- 上一轮纸面改造丢失的新增与删除入口

**不受影响**

- 不改诊断规则、批注内容、覆盖分级、版本与导出能力
- 不改领域模型与存储键的结构，只改写入时机
- 不新增依赖
