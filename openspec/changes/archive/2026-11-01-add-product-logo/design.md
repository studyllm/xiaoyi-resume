## Context

产品有两处顶栏，都写着「小奕·简历」：

| 位置 | 组件 | 现有品牌区 |
| --- | --- | --- |
| 落地页顶栏 | `frontend/src/views/WelcomeView.vue` | `<span class="landing-brand">小奕·简历</span>` + 「原型演示模式」tag |
| 工作台顶栏 | `frontend/src/layouts/DefaultLayout.vue` | `<router-link class="layout-title">小奕·简历</router-link>` + 「演示模式」tag |

品牌标识已定稿：原图是 2048×2048 的 PNG（`logo.png`，1.37MB），内容是「Y 形标记 + 小奕·简历字样」的完整组合，白底不透明。原图放进 `frontend/src/assets/` 后，代码只引用它。

约束：

- 产品名「小奕·简历」是规范里的简短品牌名，标识是图形补充，不取代文字。
- `product-visual-language` 规定界面用无衬线字体、纸面用衬线字体，两者由不同变量控制。
- 规范里「样式只使用设计变量」约束的是样式文件；图片资源是独立文件。
- `flows.spec.ts` 会扫描 `.vue` / `.css` 里的颜色字面量（`tokens.css` 除外）。

## Goals / Non-Goals

**Goals:**

- 两处顶栏都有一个可辨识的图形标识，与产品名文字并列。
- 标识的资源路径固定，换标识只覆盖文件、不改代码。
- 标识在顶栏实际尺寸下看得清，且背景透明、没有白方块。
- 标识不破坏「界面用无衬线」的字体分层（字样由界面文字渲染），也不给样式守卫添新豁免。

**Non-Goals:**

- 不做品牌设计本身：形态、配色、字样都按定稿的来，只做技术上的抠图与缩放。
- 不改产品名文字、不改两处顶栏的其它内容与版式。
- 不做多主题 logo（深色模式、折叠态等）。

## Decisions

### 决策一：资源放 `frontend/src/assets/logo.png`，代码只引用这一个文件

**选择**：新建 `frontend/src/assets/` 目录，标识文件固定叫 `logo.png`；组件里 `import logoUrl from '@/assets/logo.png'`。

**为什么**：`src/assets/` 是 Vite 的约定位置，资源经打包器处理后带哈希、走同源路径，缓存与部署都不用额外配置。文件名固定成 `logo.png`，意味着以后换标识只要覆盖这个文件，代码一行都不用动——这是「预留占位符和图片名称」这条要求最省事的落地方式。

**备选与取舍**：

- *放 `public/`*：不经过打包器，文件名原样暴露在 URL 上，且 `import` 拿不到带哈希的路径。当前没有这个目录，为一个资源新建一套约定不划算。
- *把图形内联成 Vue 组件*：能直接用 CSS 变量，但那样就不是「可替换的图片文件」了，与需求相反。
- *用 `?url` 或 public 路径硬编码*：绕过了打包器的哈希与同源处理，没必要。

### 决策二：用真实标识，图形部分单独抠出来

**选择**：标识原图（2048×2048 白底 PNG，1.37MB）里有两部分——Y 形标记（y=618..1213）与「小奕·简历」字样（y=1240..1437）。顶栏只用标记部分：裁出图形、抠掉白底、放进方形透明画布、缩到 256×256，存为 `logo.png`；原图完整组合另存 `logo-full.png` 作素材存档。

抠白底用连续 alpha 映射而不是二值化：背景的 min 通道稳定在 252–255，而光束（标记右侧那道从右上射下的光）在 223–250 之间。按 `alpha = (252 - min) / 52` 映射后，光束保留成半透明渐变，背景彻底透明，不会出现锯齿硬边。

**为什么**：图里的字样和顶栏的文字重复——24px 的高度下，图片里的字只有约 6px，既读不出来又和旁边的「小奕·简历」撞车。而原图的白底方块直接用会在顶栏露出一个白方块（落地页 hero 有桌面色渐变，工作台顶栏是纸色，都不是纯白），1.37MB 的体积对一个小图标也离谱。

**备选与取舍**：

- *整张图直接用（含字样）*：顶栏变成只有图形没有字，或者把文字换成图片——后者在 24px 下不可读，屏幕阅读器也读不到产品名。
- *抠成纯色（丢掉光束）*：图形会变成一个扁平的深蓝 Y，丢掉这张标识最有辨识度的部分。
- *保留白底方图*：在白底顶栏上看不出边界，但换个底色就露馅，且文件仍然 1.37MB。

### 决策三：标识与文字并列，不取代文字

**选择**：两处顶栏都是「标识 + 产品名文字」并排，文字保留。

**为什么**：产品名文字是规范里明确的那件事（「产品名是一个简短的品牌名」），也是用户真正用来确认「这是小奕·简历」的信息。只留图形会让顶栏失去可读性；标识只是让人更快认出来，不是替代。

### 决策四：标识做成一个组件，两处顶栏共用

**选择**：新增 `components/BrandLogo.vue`，接收 `variant` prop（`landing` / `bar`），尺寸由 CSS 变量决定，渲染 `<img>`。

**为什么**：两处顶栏要用同一个资源、同一种呈现方式（尺寸、替代文本、缩放方式）。做成组件后，「资源路径」和「装饰性 alt」这两件事只写一次，将来换图或改尺寸只改一处。

**备选与取舍**：两处各写一个 `<img>` 也行，但资源路径与 alt 规则会散落在两个文件里，守卫不好检查。

### 决策五：标识是装饰性的，不带替代文本

**选择**：`<img alt="">`。

**为什么**：标识紧挨着产品名文字，屏幕阅读器已经会读「小奕·简历」。给标识也写上替代文本就是让同一个信息被读两遍。装饰性图片的正确做法就是空 alt。

### 决策六：尺寸用变量表达

**选择**：`tokens.css` 里加 `--brand-logo-size-landing: 28px` 与 `--brand-logo-size-bar: 24px`，两处顶栏各取一个。

**为什么**：CLAUDE.md §3.1 要求字号与间距走变量。标识尺寸虽然是图片尺寸而不是字号，但同属「视觉属性」，走变量后调整只改一处，也便于守卫统一扫描。

## Risks / Trade-offs

- [标识是位图资源，它的颜色写死在自己的文件里，与「样式只使用设计变量」这条规范有张力] → 规格里明确「图片资源是独立文件，不受设计变量约束」，同时 `flows.spec.ts` 的扫描本来就不覆盖图片文件，不需要开豁免；换标识时颜色一并换掉
- [标识在 24px 下是否还看得清] → 已实测：Y 形标记在 28px 与 24px 下都能认出来，浅色光束不喧宾夺主；顶栏尺寸变量留了余量，将来要换更细笔画的标识时调这两个变量即可
- [标识是深藏青，与产品主色松墨青不同色] → 顶栏品牌文字是墨色，标识是藏青，都是深色，视觉上不冲突；标识是品牌资产，不迁就界面的功能色
- [两处顶栏的标识尺寸不同（28 / 24）] → 有意的：落地页是营销页、品牌可以更大；工作台顶栏矮，24px 刚好不挤
- [`logo-full.png` 目前没有代码引用] → 它是原素材存档（用户提供的原图被处理过，不保留就丢了字样版本）；若确定不再用，可以直接删掉

## Migration Plan

纯前端资源与模板改动，无数据结构与存档格式变更，不需要迁移。

回滚方式：`git revert` 本变更涉及的提交；`assets/logo.png`、`assets/logo-full.png` 与 `BrandLogo.vue` 是新增文件，删除即可回滚。
