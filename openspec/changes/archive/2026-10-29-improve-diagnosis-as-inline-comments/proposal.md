## Why

诊断页现在是一张**意见清单**：每条意见一张独立卡片，卡片里有原句、问题、建议。用户读到的对象是「系统挑出了 6 个毛病」，而不是「我的简历上被标了 6 处」。

问题出在**建议的载体和执行的载体分开了**。诊断给的建议是「把**这句话**改成这样」——它必须贴着那句话才能被用。但现在建议活在只读的卡片里，句子活在另一个页面的输入框里。于是「定位到句子」这个动作只带走了「哪一条要点」，把 `problem`、`suggestion`、`quote`、`highlight` 四条信息全丢在原地：

```
诊断页卡片                              编辑页
┌──────────────────────────┐            ┌──────────────────────────┐
│ ▓负责公司营销页面的前端开发▓          │ ● │ 负责公司营销页面的前端…  │
│ 问题是什么：只写了承担了什么…          │   └──────────────────────┘ │
│ 建议怎么改：补上一个可衡量的结果       │   ← 缺什么？怎么改？没了    │
│ [定位到句子]                            │   ← 也没有回到这条意见的路  │
└──────────────────────────┘            └──────────────────────────┘
```

更细的一处断裂现在还没人提：诊断页高亮的是**问题出在哪几个词**，编辑页高亮的是**整条要点**。定位过去之后，用户不知道该盯哪几个字。

这个割裂不是实现走偏，是**规格本身允许的**——主规格 `draft-diagnosis` 写的是「用户点击定位按钮 → 系统跳转到底稿编辑页 → 该要点被聚焦并高亮」，只规定了跳过去和高亮，从未要求建议跟过去。所以要改交互，必须先改规格。

## What Changes

**诊断页从「意见清单」改成「带批注的简历」**

```
┌──────────────────────────────────┬──────────────────────┐
│ 张三                             │ 批注 6   严重度▾ 类别▾  │
│ 前端工程师 · 6 年经验             │ ┌──────────────────┐ │
│ 138-… · zhangsan@…               │ │▸ 美团·前端工程师 │ │
│                                  │ │ 缺可衡量的结果    │ │
│ 工作经历 ──────────────── │ │ 建议：…           │ │
│ 美团  前端工程师   2021.03-至今   │ │ [去修改][已处理]  │ │
│ · 负责公司营销页面的前端开发 ▂▂▂   │ └──────────────────┘ │
│ · 主导活动平台前端架构升级…       │                      │
└──────────────────────────────────┴──────────────────────┘
```

- 左侧是**完整简历的只读排版**，右侧是**批注栏**。意见不再是一张张脱离上下文的卡片，而是挂在它批评的那句话旁边
- 「定位到句子」不再是跳转动作，改成**同屏高亮**——批注本来就贴着那句话
- 点批注 ↔ 点正文**双向**联动：点批注高亮左侧对应文字，点左侧文字高亮右侧对应批注

**意见按锚点挂载，分三级**

```
分区标题  ←  分区为空
条目标题  ←  缺开始时间 / 结束早于开始 / 时间区间重叠 / 顺序不对 / 缺公司名 / 缺职位 / 没有要点
要点正文  ←  只有职责没有结果 / 表述空泛
```

时间线与结构类问题本来就不针对某一句话（缺开始时间是关于整个条目的），过去只能空着 `highlight`；三级锚点让它们有地方可挂。

**编辑页同屏展示批注**

这是「割裂彻底消失」与「只是挪了个位置」的分界：用户从批注栏跳到编辑页时，屏幕上如果只有那句话和光标，建议等于又丢了——只是这次他刚看过所以记得住。**靠人脑记住就是割裂。**

因此编辑页在每条有问题的要点下方挂上它的批注，改与建议同屏。

**已改标记**

诊断是快照，底稿一改就过期。重新诊断前，用户改过的那几条要标出来，否则他改完 3 条重新诊断，发现其中 2 条的意见还在，会以为系统没生效。

**范围边界**

- 不做批注的回复与讨论（Word 的评论区），批注只承载系统给出的问题与建议
- 不改任何诊断规则、严重度分级与排序
- 诊断页的简历是**只读**的，改仍然在编辑页进行
- 批注挂载依赖已有的 `bulletId` / `itemId` / `sectionId`，不需要新的数据通道

**PRD 更新**

- §7.2 诊断：补上「意见以批注形式挂在简历对应位置，可直接看到问题出在哪几个词」
- §9 验收：新增一条——诊断页以简历加批注栏呈现，批注与被批评的文字双向联动

## Capabilities

### New Capabilities

- `resume-comment-anchoring`: 诊断意见的锚点模型（分区 / 条目 / 要点三级）、批注在简历上的挂载与双向高亮、编辑页同屏展示批注、已改与已处理状态

### Modified Capabilities

- `draft-diagnosis`: 诊断页由意见清单改为「简历 + 批注栏」；定位从跨页跳转改为同屏高亮；意见可标记为已处理
