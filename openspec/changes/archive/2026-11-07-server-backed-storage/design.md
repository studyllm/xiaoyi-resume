## Context

T3.5 的前端那一半。服务端那侧已经齐了（契约的端点全部落地），前端要接上。

## Goals / Non-Goals

**Goals**：简历与版本读写走服务端；断网有明确出路；换账号不残留上一个用户的内容。

**Non-Goals**：不动引擎、不改契约的资源清单。

## Decisions

### D1. 服务端是权威，客户端不提交算好的结构化数据

保存时服务端重跑结构检查与不变量校验（ADR-0003 的「服务端是权威」）。

**理由**：客户端提交的结构化数据可能是在本地被改过的，也可能来自旧版本。

### D2. 本地那份是只读缓存

保存成功后写一份本地缓存；读取时服务端问不到才退回缓存。断网时能看不能存。

**理由**：计划 T3.5 要求「本地缓存用于离线只读」，并且「保存时告知离线，暂不能保存」。

### D3. 保存带 If-Match 与修订号

服务端发现修订号变了就返回 `DRAFT_REVISION_CONFLICT`。

**理由**：别把别处的改动覆盖掉。账号切换后客户端的修订号是旧的，服务端要能挡住。

### D4. 换账号后要等重载完成再保存

两个 store 都记着「正在进行的重载」，保存与生成前先等它完成。

**理由**：真实环境跑出来的 bug——新建的账号在服务端没有草稿，客户端却带着上一个账号的修订号去保存，服务端判冲突（409）。等重载完成，修订号才是新的。

### D5. 版本列表返回完整版本

契约里那一行改了：一份简历的版本通常只有几十个，一并返回省掉前端逐个拉详情；`pageSize` 上限 100。

**理由**：前端要按 id 直接取版本（深链与打印页），返回摘要就得再拉一次详情。

### D6. 版本 id 是 text 不是 uuid

引擎生成的版本 id 是 `version-1` 这种，可读且可复现；表结构原来写成 uuid，插不进去。

**理由**：真实环境跑出来的 bug——真库里插入直接失败。账号与会话的 id 是服务端签发的 uuid ✓，但版本 id 来自引擎。

## Risks / Trade-offs

**[本地缓存里的内容可能过期]** → 缓存只用于「服务端问不到」时展示，且保存永远走服务端。

**[断网时保存失败]** → 界面明确告知「等连上再保存」，不假装存上了。

**[账号切换的竞态]** → 保存与生成前等重载完成；重载与保存都串行。

## Migration Plan

存量数据在浏览器本地，P3 的一次性迁移端点把它搬上服务端（`POST /api/v1/draft/import-local`）。**本地副本在迁移成功后应清除**——留在本地的 PII 残留等于没迁（P5 的隐私清单里的一条）。

## Open Questions

- 迁移成功后本地副本是自动清除还是问用户——现规格是「一键迁移、失败给明确文案与丢弃重录选项」，本地副本的清除时机还没写进规格。
