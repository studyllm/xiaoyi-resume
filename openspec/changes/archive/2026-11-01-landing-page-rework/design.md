## Context

落地页当前由 `frontend/src/views/WelcomeView.vue` 一个组件承担全部职责：顶栏、价值主张文案、CTA、登录卡、以及右侧的样例区（整页 A4 简历 + 三条批注）。`/` 与 `/login` 两个路由都指向这个组件。

1440 视口下的实测结果（本次整改的依据）：

| 位置 | 实测值 | 来源 |
| --- | --- | --- |
| 顶栏内容左缘 | 176px | `.landing-header-inner` max-width 1120 居中 + 16 padding |
| 首屏内容左缘 | 116px | `.landing-main` max-width 1240 居中 + 16 padding |
| 首屏文案栏宽 | 371px | `minmax(0, 1fr) auto`，右栏按内容固有宽度占 797px |
| 样例纸渲染宽 | 524px | 210mm × `zoom: 0.66` |
| 纸面正文有效字号 | 9.2px | 10.5pt × 0.66 |
| 批注正文字号 | 12px | `.showcase-comment-problem` |

约束：

- 纸面版式由 `ResumePreview` 唯一定义（分区标题加粗带下划线、条目头两端对齐、要点悬挂缩进），落地页不得自绘一套长得不一样的纸。
- 落地页不属于工作台布局，可以整页滚动。
- 本轮不动编辑页、诊断页、导入页、版本页的布局；存量硬编码 px 只处理落地页。

## Goals / Non-Goals

**Goals:**

- 首屏文案栏有足够宽度，主标题不在词中间断行。
- 样例区的简历正文用真实字号，批注不再比它批注的简历更醒目。
- 纸在落地页上被当成纸看待（落在桌面上，有边界）。
- 落地页只有一个实心主色按钮，两个入口动作的名字用户一看就懂。
- 用户在看到任何价值之前不被要求确认身份；身份在第一次保存时才问，且只要一个名字。
- 顶栏与首屏内容左右边缘对齐。
- 落地页的样式走设计变量。
- 三类问题今后能被守卫测出来：跨组件同屏实心主色、落地页样式字面量、批注严重度与纸面高亮不一致。

**Non-Goals:**

- 不重做工作台布局，不改编辑页、诊断页、导入页与版本页的版式。
- 不给样例区做批注与纸上要点的双向联动（首屏静态对应即可）。
- 不清理其它组件里的存量硬编码 px（`CommentSidebar` 23 处、`VersionDetailView` 12 处等），那是另一轮的事。
- 不做响应式断点体系，只保证窄屏不溢出。
- 不做真实的账号体系：没有密码、没有注册、没有服务端校验。

## Decisions

### 决策一：样例区用裁剪后的数据，不做 CSS 裁切，也不缩放整页

**选择**：把 `mock/showcase.ts` 里的样例数据裁剪成「工作经历」分区 + 美团那一条经历（4 条要点，其中 3 条被批注），`profile` 传空让抬头不渲染，然后按片段尺寸渲染。

**为什么**：整页 A4 在首屏只有 524px 宽，正文必然被压到 9px 左右；而真正的信息量是「一句话被诊断出什么问题」，整页简历反而稀释了重点。裁剪数据后，纸自然就是一段「工作经历」，正文用 10.5pt 的真实字号，读者一眼看清批注指的是哪句话。

**备选与取舍**：

- *CSS 裁切整页 A4*（负 margin + overflow hidden）：能保留完整简历的观感，但裁切窗口的位置与缩放比例要手工调，数据一变就错位；而且「纸的上半部分被放大」这个视觉本身仍然不解决字号问题。
- *用 transform: scale 整体缩放*：比 `zoom` 可控，但布局尺寸不跟着变，容器要额外用负 margin 补偿；且批注与纸的相对比例仍然要靠手调。
- *把批注栏也一起缩放*：能保住相对关系，但批注本身就得缩到 10px 以下，批注作为主信息反而更小。

### 决策二：给 `ResumePreview` 增加 `variant`，不改它的默认形态

**选择**：新增 `variant?: 'page' | 'fragment'`，`fragment` 时纸宽用 `--paper-fragment-width`、去掉 A4 最小高度、内边距收紧、外层 `.resume-preview` 去掉自身 padding。默认仍是 `page`。

**为什么**：用 `:deep()` 从落地页穿透去改 `ResumePreview` 的内部宽度，等于让两个页面共享组件的私有尺寸约定——以后谁改 `ResumePreview` 都会踩到落地页。让「片段」成为组件的一种显式形态，样式收在组件内部。

**备选与取舍**：新增一个独立的 `ShowcaseFragment.vue` 组件。它可以完全按落地页需要定制，但会复制一套纸面版式（分区标题、条目头对齐、悬挂缩进），与真实纸面长得不一样，违反「纸是内容的承载形式」。

### 决策三：落地页容器宽度 1280px，首屏两栏 560 / 656

**选择**：新增 `--landing-width: 1280px`，顶栏与主内容共用它。首屏 `grid-template-columns: minmax(0, 560px) minmax(0, 1fr)`，列间距 32px。文案栏 560px，样例区 656px。样例区内部再分：纸画布 400px + 间隙 16px + 批注栏 240px。

**推导**：

- **文案栏 560px**：大标题在 28px 下实测 528px 宽，560px 能一行放下（余量 32px）。之前标题跨满整行 1248px 而文字只占 528px，右上方空出 694px——那是「怪」的第一个来源。
- **纸画布 400px**：纸本身 352px（减去 24px×2 的画布内边距），内文可用 352-48-34 = 270px，14px 字号下每行 19 字，长要点自然折成两行——恰好是批注要指出的问题形态。
- **批注栏 240px**：批注正文 12px，每行约 18 字，问题一句两行。
- **纸的高度**：加了「教育背景」分区后 389px；批注三条各 149px，合计 463px。两栏差 74px，批注不再垂在纸下一大截。

**为什么不沿用工作台的 1120px**：落地页是营销页，首屏要同时放下价值主张和样例，1120px 下样例区只剩 610px，纸片段得压到 340px 才放得下批注栏，字号又要回到不可读。落地页有独立宽度，与工作台不一致是合理的；要求的是落地页**自己**顶栏与内容对齐。

### 决策三之二：特性清单进文案栏，不再在首屏下方另起一排

**选择**：三个特性从首屏下方的横排卡片区搬进文案栏，成为标题、副文案、CTA 下面的一段清单（带一条上边框分隔）。首屏下方不再有内容。

**为什么**：按 560 / 656 切完之后，文案栏只有 176px 内容、样例区 463px，左下空出 287px——那正是「怪」的第二个来源，而这版布局改动本身填不掉它。三个特性搬进左栏后，文案栏 422px、样例区 463px，差 41px，首屏读起来是一个完整的构图。

**为什么不用「左栏垂直居中」来消化那段空白**：垂直居中会把大标题压到样例区顶部以下 140px，两栏顶端就不齐了——顶部齐平比底部齐平重要得多，因为视线先落在标题上。

**备选与取舍**：

- *特性留在下方横排*：卡片形态好看，页面底部也有一排内容收尾，但左下那 287px 的空洞就是首屏最大的问题。两害相权，取空洞小的。
- *把页脚的原型说明搬进左栏*：能填 60px，但填不平 287px，而且页脚会空掉；说明放在页脚本来就是它该在的位置。

### 决策四：身份入口收敛为一个对话框

**选择**：删除 `components/LoginCard.vue`，新增 `components/IdentityDialog.vue`（`el-dialog`，居中，默认尺寸）。路由守卫把未登录用户重定向到 `/` 并带上 `redirect` 参数，落地页读到 `redirect` 就自动打开对话框；导入页第一次点「保存」时也打开它（见决策八、十）。

**为什么**：现状是 `/` 与 `/login` 渲染同一个组件，未登录点 CTA 会被守卫弹回同一页面，屏幕毫无变化——用户以为按钮坏了。合并成一处之后，身份入口只有一个，确认后能自然地继续去原本要去的页面。

**备选与取舍**：

- *保留独立的 `/login` 页*：多一处入口要维护，且用户在落地页点 CTA 仍然会「页面跳了一下但长得一样」。
- *落地页内嵌身份卡*：就是现状，两个实心主色同屏。
- *点 CTA 直接用演示身份登录*：省掉一次输入，但把「这份简历是你的」这个概念从原型里抹掉了，与 `account-access` 现有行为不符。

对话框是覆盖在页面之上的独立交互层，层内允许一个实心主色按钮，不与被遮住的页面主按钮合计。这是 `product-visual-language` 里「一个界面上至多一个实心主色」的例外，需要写进规格。

### 决策五：批注卡按严重度着色，与纸面高亮共用一套变量

**选择**：样例批注卡的左边框与锚点行使用 `--severity-high/medium/low` 及其 ink/soft 变量，class 由每条批注的 severity 决定，与 `DiagnosisComment.vue` 保持同一套写法。

**为什么**：现在三条批注的左边框与锚点行都写死 `--severity-medium`，而纸上第三条（low）的高亮是灰蓝色——同一个严重度在两处显示成两种颜色。批注卡与纸面高亮必须同源，否则「批注锚定到具体句子」这件事在视觉上就断了。

### 决策六：守卫补强的落点

现有 `flows.spec.ts` 的「一个界面上至多一个实心主色」按**文件**统计，`WelcomeView.vue` 一个实心主色、`LoginCard.vue` 一个实心主色，各自都合法，但同屏出现两个——守卫看不见。这次补三条：

| 守卫 | 落点 | 断言什么 |
| --- | --- | --- |
| 落地页层的实心主色 | `flows.spec.ts` | 把 `WelcomeView.vue` 视为落地页层，`IdentityDialog.vue` 视为独立交互层；层内实心主色 ≤1 |
| 落地页样式字面量 | `flows.spec.ts` | 只扫 `WelcomeView.vue` 的 style 块，`font-size`/`padding`/`margin`/`gap` 的 px 字面量为 0。**理由登记进白名单**：存量其它组件有 80 余处硬编码，本轮不动，只把落地页纳入 |
| 批注严重度标记 | `views/WelcomeView.spec.ts` | 每张批注卡带对应其严重度的 class，不同严重度的批注卡 class 不同。**只断言 DOM 上的 class，不断言 CSS 字符串**——静态扫描测不到实际效果，断言 CSS 字符串只会制造「改了样式测试也不报」的假安全感 |

另加 `views/WelcomeView.spec.ts` 的行为测试：未登录点 CTA 直接进入导入页、带 `redirect` 进来时身份对话框自动打开、确认后回到目标页、顶栏与主内容使用同一个容器 class。`components/IdentityDialog.spec.ts` 覆盖表单校验与提交。

**为什么不用 CSS 扫描来做「顶栏与内容对齐」**：对齐是渲染结果，静态测不到；改成断言两个容器使用同一个 class，把约定固定在代码结构上。

## 文案与身份时机

### 决策七：身份只要一个名字，不要密码

**选择**：身份对话框只保留一个「你的名字」字段，密码字段整个去掉；`session.login` 也不再接收密码。

**为什么**：现在的表单在撒谎——它问了密码，密码却什么也不做。用户认真设一个密码，下次清了浏览器数据就没了，这种「承诺了却不兑现」的表单比不提供更糟。而「随便写一个」的提示是自曝：它告诉用户这里没有校验，那用户为什么要填；同时它把「认真填」和「乱填」的价值拉平了，偏偏「你的简历归你」这件事里名字是唯一有所谓的部分——名字会显示在顶栏、出现在简历的归属上，填了有反馈，不填无意义。

原型只跑在本机，密码从来没有、也不应该有实际用途。去掉它之后，表单问的每一个字段都有真实用途。

**备选与取舍**：

- *保留密码但说明不做校验*：这就是现状，用户依然要为一个不存在的凭据编一个值。
- *保留密码并真的校验*：原型没有后端，存密码意味着要在本机存一份明文密码，代价与收益完全不成比例。

### 决策八：身份推迟到用户第一次保存时

**选择**：落地页主按钮不再弹任何对话框，直接进导入页；粘贴、解析、在纸上改全程免登录；导入页第一次点「保存」时才弹身份对话框，确认后这次保存继续完成。未登录访问其它受限页面（编辑、诊断、版本）仍然落到落地页并自动打开身份对话框，确认后继续去目标页。

**为什么**：登录在这个产品里真正的作用只有保存简历与生成版本两处，所以问题不是「登录长什么样」而是「什么时候问」。用户还没看到任何价值就要先完成一次注册，是试用陌生工具时最常见的流失点；而推迟到保存时再问，用户已经看到了解析结果、知道这工具对自己有用，这时被问「这份简历要存在这台设备上，叫什么名字？」是有动机的，回答率会高得多。

**备选与取舍**：

- *完全不要身份，直接以演示身份保存*：最省事，但所有访客的简历都叫「演示用户」，用户对「这份简历是我的」没有归属感，而归属感正是这个原型唯一能给的东西。
- *保留独立的登录页*：多一处入口要维护，且用户在落地页点主按钮仍然会「页面跳了一下但长得一样」。

### 决策九：落地页按钮的文案

**选择**：无草稿时主按钮是「导入我的简历」，有草稿时是「打开我的简历」；旁路按钮统一为「用示例简历试一遍」。

**为什么**：「直接看样例数据」是数据视角的词，可求职者看到的是一份简历；「直接」和旁边的主按钮并列，两个都像主路径，弱化了它其实是「先随便看看」的旁路。改后的旁路用「试一遍」明确它是可选的试用路径而不是第二条主路径。

「导入」与导入页标题、界面统一称呼「我的简历」都对得上；导入页确实有粘贴与上传两种方式，用「导入」统称准确。

「打开我的简历」只在用户已有简历时出现，和侧栏里那一项同名：点之前就知道会看到什么，落点也对得上。

考虑过用「进入工作台」，否决了：「工作台」这个词在界面上一次都没出现过——它只活在 `workspace-layout` 规范和 CLAUDE.md 里，是给开发看的内部叫法；放到按钮上用户会问「工作台是什么」。而且侧栏里有四项（我的简历 / 简历诊断 / 按 JD 生成 / 多 JD 版本），「工作台」是这四项的容器而不是其中任何一项，按钮说的是容器而不是用户能得到什么。

### 决策十：身份对话框的两个宿主

**选择**：`IdentityDialog.vue` 是一个组件，两个宿主各自管理何时打开它——落地页（未登录访问受限页面后自动打开）与导入页（点保存时打开）。导入页用「确认后继续保存」的回调方式衔接。

**为什么**：对话框放在全局布局里、再用 store 协调「谁在等身份」，会为了两个使用点引入一套跨组件的状态机。放在宿主里，宿主各自决定何时需要身份，逻辑直白。

**备选与取舍**：统一挂到 `DefaultLayout` 上、公开路由区也带上，机制更统一，但落地页与导入页要共享一套「待办动作」的状态，实际并没有第三种场景，抽象是多余的。

### 决策十一：路由守卫用 `requiresLogin` 而不是 `public`

**选择**：路由 meta 新增 `requiresLogin`，导入页设为 `false`；`public` 保持原义（公开路由不套工作台布局）。

**为什么**：`meta.public` 在 `DefaultLayout` 里控制着「是否渲染工作台顶栏与侧栏」。若用 `public` 放行导入页，导入页会失去工作台布局——用户粘贴简历时看不到侧栏与顶栏，与其它页面割裂。所以这两个语义必须分开。

## Risks / Trade-offs

- [落地页容器 1280px 比工作台 1120px 宽，两套宽度并存] → 落地页是有意与工作台不同的营销页；用独立变量 `--landing-width` 表达，不复用 `--paper-width` 或 `.page`，避免以后被误当成全局宽度
- [给 `ResumePreview` 加 `variant` 会碰到编辑页、诊断页共用的组件] → 默认值保持 `page`，现有三个使用点不传该 prop；改完跑全量测试与类型检查，并在浏览器里过一遍编辑页与诊断页
- [守卫按文件统计的盲区仍在，只堵住了落地页这一处] → 其它页面（导入页是白名单例外）没有同屏多主色问题；将来若有跨组件同屏场景，需要引入「层」的概念，本次不提前抽象
- [样例只展示一条经历，读者看不到完整简历] → 落地页要传达的是「批注锚定到句子」这件事，一条经历比整页更聚焦；完整简历在「用示例简历试一遍」之后的工作台里
- [批注栏（264px）比纸（220px）高] → 批注栏顶部与纸顶部对齐，超出部分向下延伸；这是诊断页批注栏的常态，不刻意居中
- [落地页样式改成全变量后，若将来改 tokens 里的 `--space-*`，落地页间距会一起变] → 这正是要走变量的目的
- [匿名用户能在导入页粘贴任意简历文本，解析结果会短暂占内存] → 原型全在本机，解析不出网；解析结果不落盘，用户不确认身份就离开，什么都不会留下
- [未登录用户在工作台里看到空的顶栏用户区] → 未登录时顶栏不渲染头像与「退出登录」；匿名用户本来就没有用户信息，显示一个空壳更糟
- [「导入页免登录」之后，匿名用户点侧栏的受限项会回到落地页] → 这是有意的：身份对话框会说明「留个名字就能继续」，用户确认后直接回到原目标页

## Migration Plan

纯前端布局、交互与文案改动，无数据结构与存档格式变更，不需要迁移。

回滚方式：`git revert` 本变更涉及的提交；`IdentityDialog.vue` 与 `LoginCard.vue` 是新增与删除的替换关系，不存在中间态存档。

`session.login` 的签名从 `(username, password)` 变成 `(name)`，只影响调用方，不影响已存的登录态结构——存档里的 session 结构没有变化。
