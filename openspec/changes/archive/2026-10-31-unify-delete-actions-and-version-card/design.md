## Context

删除动作在界面上有四种样子（图标/文字 × 常显/悬停 × 有无确认），版本卡片的底部把时间和四个按钮挤在一行。两处都是"没有统一"造成的，不是设计失误。

规格里其实已经有过规定，只是实现没跟上：`resume-draft`「可删除条目与要点」写着"删除入口 SHALL 出现在被删除对象旁边，且 SHALL 在对象被悬停时才出现，以免纸面上常年挂着按钮"——纸面上条目与要点的删除是常显的；`version-management`「版本列表展示底稿入口与全部版本」写着"每个版本 SHALL 展示名称、对应 JD 与生成时间"——但没说这些信息怎么排。

产品负责人这次的要求是：删除一律用垃圾桶图标；卡片上时间与操作各占一行。

## Goals / Non-Goals

**Goals:**

- 所有删除入口长得一样：同一个垃圾桶图标、同一套颜色规则、同一套二次确认
- 删除入口不用红字常显在纸面上，但也不能藏到找不着
- 版本卡片的时间与操作各占一行，窄卡片不挤

**Non-Goals:**

- 不改删除的语义（都是二次确认后才真删）
- 不动「忽略此条」这类非删除的操作
- 不改版本数据与生成逻辑

## Decisions

### D1 删除入口 = 垃圾桶图标 · 淡色常显 · 悬停变红

```css
/* styles/main.css，纸面与版本卡片共用 */
.paper-delete.el-button--text {
  padding: 0 2px;
  color: var(--ink-300);
}

.paper-delete.el-button--text:hover {
  color: var(--severity-high);
}
```

颜色用现有的 `--ink-300`（淡）与 `--severity-high`（警示），都在 `styles/tokens.css` 里，不新增字面量。

样式放在 `main.css` 而不是编辑器的 scoped 样式里：纸面与版本卡片是两个组件，要共用同一套规则。

**为什么不用「悬停才出现」**：规格原本那么写，是为了让纸面干净。但现在入口是一个没有文字的图标——藏起来就没人知道那能删。所以反过来：一直显示，但用淡灰色，不抢眼；鼠标移上去才变红。

**为什么不用红字常显**：那是现在条目与要点的样子，纸面上两排红字「删除」很吵。

### D2 二次确认也统一，联系方式补上

纸面三处删除都是原地的二次确认（点一下变成「确认删除？」+「取消」）。联系方式原来点了直接删——删除不可撤销却没有确认，跟另外两处不一致，补上。

用 `contact-${index}` 作为确认态的目标标识，跟条目、要点的标识分开。

版本卡片用的是气泡确认（`el-popconfirm`），它不在纸上，没有"原地变成确认态"的位置，保持现状。

### D3 卡片底部拆两行

```html
<div class="version-card-meta">生成于 2026-10-31 16:20</div>
<div class="version-card-actions">[打开][复制纯文本][导出 PDF] 🗑</div>
```

分隔线跟着时间那一块（`.version-card-meta` 的 `border-top`），操作行不再带分隔线。

**为什么不是"同一行、左右分列"**：卡片最窄 320px，减去内边距约 292px；左边的时间串（约 130px）加右边四个操作（约 220px）放不下，flex 换行后两拨东西会错位——这就是现在乱的原因。分成两行以后，操作按钮自己换行也影响不到时间。

## Risks / Trade-offs

- **[删除入口不再藏起来，找不到的人会觉得少了个按钮]** → 淡色常显 + 悬停变红；点错还有二次确认挡着
- **[联系方式加确认多一步]** → 与另外两处一致；删除不可撤销本来就该有这一步
- **[图标按钮没有文字，读屏软件读不出来]** → 每个图标按钮都带 `title` 与 `aria-label`
- **[卡片变高一行]** → 每张卡多约 20px；换来时间不再被顶开

## Migration Plan

纯前端改造，无数据迁移。改动集中在两个组件、一份共享样式与一份规格。回滚即还原这几个文件。

## Open Questions

- 版本卡片里「复制纯文本」和「导出 PDF」也带图标，「打开」是纯文字——同一排按钮形态还不完全一致。要不要统一成全图标，等下次动这块时一起看
