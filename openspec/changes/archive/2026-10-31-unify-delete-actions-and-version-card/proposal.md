## Why

两处界面问题，都是"没有统一"造成的。

**一、删除入口有三种做法。** 同一个"删除"动作，界面上有四种样子：

| 位置 | 现在 | 悬停才出现 | 二次确认 |
|---|---|---|---|
| 纸面·联系方式 | 🗑 图标 | 是 | **没有**，点了直接删 |
| 纸面·条目 | 文字「删除」 | 否，常显 | 有（原地变确认态） |
| 纸面·要点 | 文字「删除」 | 否，常显 | 有（原地变确认态） |
| 版本卡片 | 文字「删除」 | 否 | 有（气泡） |

规格里本来就写着「删除入口 SHALL 出现在被删除对象旁边，且 SHALL 在对象被悬停时才出现，以免纸面上常年挂着按钮」——纸面上条目与要点的删除是常显的，跟规格对不上；反过来"一直显示"和"悬停才出现"两种做法各占一半，也不齐。

**二、版本卡片的底部挤在一行。** `.version-card-foot` 是一行 flex，左边「生成于 2026-10-31 16:20」，右边四个操作按钮（打开 / 复制纯文本 / 导出 PDF / 删除）。卡片最窄 320px，两拨东西挤在一行 → 时间被顶开、按钮换行。

## What Changes

**删除入口一律是垃圾桶图标**

```
删除入口 = 🗑 图标 · 淡色常显 · 悬停变红 · 二次确认
```

- 淡色常显（`--ink-300`）不抢眼，又不像现在那样常显着红色「删除」两个字
- 悬停变警示色（`--severity-high`）
- 纸面三处（联系方式、条目、要点）与版本卡片用同一个图标、同一套颜色规则（放在 `styles/main.css` 里共享）
- 二次确认也统一：纸面三处都是原地的「确认删除？/取消」。联系方式原来点了直接删（不可撤销却没有确认），补上

**版本卡片：时间一行，操作一行**

```
┌─────────────────────────┐
│ 前端工程师-字节跳动  [修订号 3] │
│ 负责前端架构…（两行摘要）    │
│ ─────────────────────── │
│ 生成于 2026-10-31 16:20   │
│ [打开][复制纯文本][导出 PDF] 🗑 │
└─────────────────────────┘
```

时间单独占一行（上面带分隔线），操作另起一行——卡片收窄时按钮换行也不会把时间顶开。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `product-visual-language`: 新增「删除入口统一用垃圾桶图标」
- `resume-draft`: 「可删除条目与要点」——删除入口的形态改成淡色常显的垃圾桶图标；联系方式的删除与条目、要点一致
- `version-management`: 「版本列表展示底稿入口与全部版本」——卡片上生成时间与操作分行

## Impact

**代码**

- `frontend/src/styles/main.css`：删除图标的共享样式
- `frontend/src/components/ResumeEditor.vue`：三处删除入口改成图标；联系方式补上二次确认
- `frontend/src/components/resume-editor.css`：删掉 `delete-reveal`（删除入口不再靠悬停出现）
- `frontend/src/views/VersionsView.vue`：卡片底部拆两行；删除改成图标

**不受影响**

- 不改删除的行为语义（都是二次确认后才真删）
- 不改版本数据与生成逻辑
- 不改「忽略此条」这类非删除的操作
- 不新增依赖
