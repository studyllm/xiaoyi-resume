## Context

模型调用失败时，服务端只把状态码放进错误消息。服务商给的正文——那句唯一说得清原因的话——被丢掉了。

## Goals / Non-Goals

**Goals:**

- 失败记录里有服务商自己说的原因。

**Non-Goals:**

- 不改降级链（模型不可用仍回落规则引擎）。
- 不改重试判定。
- 不把服务商正文原样透给用户界面——它进的是日志与生成日志，不是界面文案。

## Decisions

### D1. 优先取 `error.message`

OpenAI 兼容的形状是 `{"error":{"message":"…"}}` ✓ —— 那是服务商写给开发者看的话 ✓。取不到就退回正文本身（有的服务商会回纯文本 ✓）。

### D2. 截到 300 字

正文可能很长（有的服务商会回整个堆栈 ✓）。日志与生成日志里不需要全文 ✓。

### D3. 不记请求内容与凭据

正文是服务商的错误说明 ✓，不含我们的请求体 ✓。但为了稳妥，只取 `error.message` 或 `message` 两个字段 ✓ —— 不把整段正文里的未知字段带出去 ✓。

## 验证方式

- `server/src/llm/client.spec.ts`：
  - 服务商给了结构化说明 → 错误消息里有那个说明
  - 服务商给了纯文本 → 错误消息里有正文
  - **两条用例在修复前都是红的**（`but got '模型返回 402'`）✓
- 手工：用配好的 MiniMax 配置跑一次生成 → 生成日志的 error 字段是「模型返回 402：insufficient balance (1008)」✓
- 仓库根 `npm run verify` 全绿。
