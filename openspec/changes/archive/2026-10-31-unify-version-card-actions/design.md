## Context

版本卡片底部的操作按钮一排四个，但形态不统一、也没对齐：

```
[打开] [📋 复制纯文本] [⬇ 导出 PDF] [🗑]
 ↑ 没有图标
```

- 「打开」是纯文字，别的三个是图标+文字 → 它的文字比旁边按钮的图标靠左 11px，一排按钮看起来是错开的
- 删除按钮在上一轮统一删除入口时，为了收紧宽度单独设了 `padding: 0 2px` → 它的图标比别的按钮的图标又靠左 9px

两个错位都只有把四个按钮放在同一行、逐个量偏移才看得出来。

## Goals / Non-Goals

**Goals:**

- 卡片上的操作按钮形态一致：都是图标 + 文字
- 四个按钮的图标与彼此对齐（同一基线、同一左偏移）

**Non-Goals:**

- 不改按钮的行为与文案
- 不改卡片的其它排布
- 不动纸面上的删除入口（那一处只有一个按钮，没有同排对齐的问题）

## Decisions

### D1 四个按钮都带图标

「打开」补上 Element Plus 的 `View`（眼睛）——看这一版是什么，跟旁边「复制纯文本」「导出 PDF」一个路数。

### D2 删除按钮不再单独收窄内边距

```css
/* styles/main.css */
.paper-delete.el-button.is-text {
  color: var(--ink-300);
}
```

去掉 `padding: 0 2px` 后，删除按钮用组件库默认的内边距，跟同排三个按钮一致 → 四个图标的左偏移都是 11px。

**为什么上一轮要收窄**：当时纸面上的删除按钮是文字「删除」，字间距大、红色扎眼；换成图标之后视觉体积小了很多，就不需要额外收窄了。上一轮的收窄在卡片这排按钮上留下了错位。

## Risks / Trade-offs

- **[四个按钮变宽，窄卡片里可能换行]** → 卡片最窄 320px，减内边距约 292px；四个按钮（图标 14 + 文字 20~60 + 内边距）合计约 250px，仍能放下；真放不下时 flex 会换行，而时间已经独占一行，换行不影响它
- **[眼睛图标可能被理解成"预览"而不是"打开"]** → 版本详情页本身就是预览简历的地方，「打开」进入的是详情；文案保持「打开」不变，图标只是辅助

## Migration Plan

纯前端改造，无数据迁移。改动两个文件、几行。回滚即还原。
