## Why

原型目前没有自己的视觉语言：界面是标准 Element Plus 后台面板的样子——66 处硬编码颜色、4 个 CSS 变量、从未覆盖过组件库主题。换句话说，界面在功能上是对的，但**看起来不像这个产品**。

更具体的问题是同一个产品里存在三种形态：

```
编辑页                 诊断页                版本列表
┌──────────────┐      ┌──────────┬──────┐   ┌──────────────┐
│ ▭ 抬头 ▭ ▭ ▭  │      │          │ ▓批注 │   │ el-table      │
│ ┌──┐┌──┐┌──┐  │      │   纸     │ ▓批注 │   │              │
│ │张││前││至│  │      │          │      │   └──────────────┘
│ └──┘└──┘└──┘  │      └──────────┴──────┘
└──────────────┘
 表单控件文档          文档 + 批注          后台表格
```

而这个产品的本质是**在一份简历上批注**。诊断页那套气质是对的（纸 + 批注），但它只活在一个页面里，其余页面还是表单和表格。用户看完产品说不出它长什么样。

还有一处功能性的问题被视觉问题掩盖了：上一轮把诊断改成批注形态后，编辑页仍是表单，批注被塞在输入框下面——两种形态对不上。

## What Changes

分三个阶段，阶段一与阶段二是**收敛**，阶段三是**表达**。

**阶段一：设计变量层**

- 建立 `tokens.css`，把颜色、字号、圆角、阴影、间距收敛成变量；组件里不再写死这些值
- 主色定为**松墨青 `#0F766E`**，通过覆盖 Element Plus 的变量阶梯生效，不引入 sass
- 颜色分工明确：**主色管"可操作"，语义色管"有问题"**。批注严重度占用红/琥珀/板岩灰，主色避开这三者

**阶段二：交互规范**

- 破坏性操作（删除条目、删除要点、删除版本）默认不出现，悬停或展开后才现
- 主操作、次操作、危险操作三档用法固化，主操作不再满屏蓝色
- 演示模式提示从全宽警告条降噪
- 侧栏菜单按「工作 / 交付」分组

**阶段三：纸面为主角**

- **编辑页**：分区页签 → 长纸 + 左侧分区目录 + 右侧批注栏。纸上的抬头、条目、要点就地编辑
- **诊断页**：已是「纸 + 批注栏」，做视觉统一并让纸只读
- **版本列表**：表格 → 卡片，每张卡片是一份简历
- **落地页**：首屏用一份真实的简历配几条批注，直接演示产品在做什么

字体分层：**界面无衬线，纸面衬线（宋体）**。阶段三之后纸就是编辑器本身，导出与所见仍然同源。

**范围边界**

- 不新增任何 npm 依赖（主题覆盖走 CSS 变量，不引 sass）
- 不改任何业务逻辑：诊断规则、覆盖分级、排序护栏、删减闸门、措辞变换全部不动
- 不改数据模型与存储键
- 不做暗色模式——简历是要打印和投出去的，暗色没有意义

## Capabilities

### New Capabilities

- `product-visual-language`: 设计变量层、主色与组件库的一致性、颜色的语义分工、字体分层、"纸"作为内容承载形式这几条可校验的视觉契约

### Modified Capabilities

- `draft-diagnosis`: 编辑页改为以纸承载内容，批注展示在纸右侧的批注栏而非要点下方
- `version-management`: 版本列表以卡片呈现，每个版本一张卡片

## Impact

**代码**

- 新增 `frontend/src/styles/tokens.css`：设计变量与 Element Plus 主题覆盖
- `frontend/src/styles/main.css`：改为引用变量，收敛工具类
- `frontend/src/layouts/DefaultLayout.vue`：顶栏、侧栏分组、演示模式提示降噪
- `frontend/src/views/DraftView.vue`：分区页签 → 长纸 + 分区目录 + 批注栏（结构改动最大）
- `frontend/src/views/DiagnosisView.vue`：与编辑页统一为同一套布局
- `frontend/src/views/VersionsView.vue`：表格 → 卡片
- `frontend/src/views/WelcomeView.vue`：首屏改为真实简历 + 批注
- `frontend/src/components/ResumePreview.vue`：纸面样式改用变量，字体改衬线
- `frontend/src/components/CommentSidebar.vue`、`DiagnosisComment.vue`：严重度色改用变量

**护栏**

- 新增一条测试：扫描界面样式里的颜色等视觉字面量，除设计变量文件外一律视为不合规

**与规格的关系**

主规格此前落后于实现三轮（`resume-terminology`、`resume-preview-and-export`、`resume-comment-anchoring` 三条能力与其增量），现已全部补齐并校验通过。

因此本变更的增量收敛为三条：`product-visual-language` 作为新增能力；`resume-comment-anchoring` 只改「编辑时批注与句子同屏」一条（编辑页改为纸承载）；`version-management` 只改「版本列表展示底稿入口与全部版本」一条（改为卡片）。`draft-diagnosis` 不需要改动——主规格已是批注形态，而本变更不改它的行为。

**不受影响**

- 不新增依赖，不产生网络请求
- 引擎层、领域模型、持久化结构完全不动
