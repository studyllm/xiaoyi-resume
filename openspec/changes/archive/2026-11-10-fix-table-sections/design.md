## Context

前两轮修完结构检查的假阳性与条目头切分，剩下的问题全在一张表上。PDF 里的表格，列是分开的，扁平化之后列的顺序就乱了：

```
2018.11 云宠
主导电商核心商品模型设计,实现支持多规格、动态属性的灵活
- SaaS电
SKU配置体系
2019.04 商平台
```

按条目头去切，切出的是「云宠」「商平台」「浙江省助」「统」这样的碎片。

## Goals / Non-Goals

**Goals:**

- 表格不再被切成碎片条目。
- 表格的内容一行不丢，用户看得见那是什么表。

**Non-Goals:**

- **不把表格还原成结构化条目**——那要动提取层。
- 不改前两轮的成果（重叠判定、自动排序、条目头切分）。

## Decisions

### D1. 认出列标题行：三个短词、不含日期、下一行含日期

列标题行长这样：「时间 项目名称 核心职责与成果」——不含日期、由三个以上空格分隔的短词组成，而且下一行含日期（表格第一列通常就是时间）。

**「下一行含日期」是防误判的关键。** 普通要点写成「负责 前端 后端」也像表格头，但它的下一行多半不含日期。判错的代价太大——整个分区剩下的行都会变成要点，条目全部消失。

带项目符号的行直接排除：要点不是列标题。

### D2. 表格的内容进「其它」分区，连同它的标题

表格不是经历条目。放进「其它」分区有两个好处：

- 「其它」分区没有条目头，结构检查不对它提缺字段的意见 ✓
- 内容不会被粘在某个项目的要点下面（那会让人以为那是那个项目的内容）✓

表格的标题（「其他项目经历」）在表头前一行，本来会被当成上一条的要点——认到表头时把它摘下来，跟表格内容一起放。

### D3. 表格还原要动提取层，这一轮不做

PDF 的表格是按坐标排的：列有各自的 x 范围，单元格里的文字还会换行。扁平化成文本之后，「云宠电商SaaS系统」这个名字被拆成「云宠」/「SaaS电」/「SKU配置体系」三段，还和职责交错。

真要还原，得在提取层按 x 坐标聚类成列、再按行带重组单元格——那是一件事，而且要防住「普通两端对齐的正文被误判成表格」这个风险。不在这一轮。

## 验证方式

- `packages/shared/src/engines/parseDraft.spec.ts`：
  - 认出列标题行 → 项目经历里没有条目，表格内容在「其它」分区里原样保留
  - 普通要点不会被误判成表格 → 工作经历的条目还在
- **那份 PDF 当回归样本**：结构问题只剩 1 条 low（教育背景没有要点——那是真的），用户界面上看不到。
- 仓库根 `npm run verify` 全绿。
