## Why

上一轮把结构问题做成了纸上的就地标注，复查下来两个毛病。

**一、时机不对。** 新增一段教育经历，纸面立刻跳出「缺少专业、缺少学校名称」。用户还没往那两栏里写字呢，提示先到了。这是在编辑过程中一轮一轮地打断他。

**二、位置不对。** 标注是 `inline-flex` 塞在条目头那一行里的，`max-width: 45%`，和公司、职位、时间抢宽度。标注一出现，输入框就被挤扁——**结构问题占掉了编辑简历的显示区域**。

原则是：**优先保证简历内容编辑的显示区域**。编辑的时候，纸上只有简历内容。

## What Changes

**编辑过程中，纸面不再出现任何结构问题提示**

纸上的 `⚠ 缺少开始时间` 那一枚 chip 全部删掉，条目头那一行还给内容本身。`ResumePreview` 里只服务标注的两个插槽（`#section-extra`、`#item-extra`）一并删掉。

**结构检查延后到保存时做**

```
编辑中                          点「保存」
┌──────────────┬──────────┐    ┌──────────────┬──────────────────┐
│              │ 批注 4    │    │              │ ⚠ 保存时发现的 3 处问题 │
│   纸面        │ 高 2 中 2 │    │   纸面        │ · 教育经历「清华」缺少专业 │
│   只有内容     │ 低 0     │    │   只有内容     │ · 工作经历「美团」缺少开始时间│
│              │          │    │              ├──────────────────┤
└──────────────┴──────────┘    └──────────────┴──────────────────┘
                                点清单某一条 → 纸面滚到那个条目，
                                光标直接落进缺的那个格
```

- 保存时跑一次结构检查，结果列在右侧批注栏顶部的一块清单里
- **不拦保存**：内容先存下来，提示放在一边
- 保存后还有结构问题就**留在编辑模式**（清单就在眼前，可以逐条点进去补）；都补完了就**切到预览**看成品
- 清单是**上一次保存时的快照**，不实时跟着改——实时就又变成"边写边提醒"

**清单要能点了就跳到那个格**

每条结构问题补一个 `field`，指出该在哪个栏里补（`org` / `title` / `start` / `end`）。编辑器接受两种新的定位指令：定位到某个条目、定位到某个条目里的某个字段。

**提示只有一个出处**

页头预览模式里的「N 处结构问题」去掉，别两处都挂。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `resume-comment-anchoring`: 移除「结构问题就地标注」——纸面不再标注结构问题
- `resume-draft`: 「解析遗留问题提示」改为"编辑过程中纸面不出现结构问题标注，结构问题在保存时检查、结果显示在右侧栏"；「结构标注用同一套说法」改为「结构问题清单用同一套说法」
- `prototype-runtime`: 「编辑行为承载在可独立挂载的组件中」的场景改为"编辑器在编辑过程中不在纸面上标注结构问题"

## Impact

**代码**

- `frontend/src/engines/structure.ts`：每条 finding 增加 `field`，指出该在哪个栏里补
- `frontend/src/components/ResumeEditor.vue`：删掉纸面标注与相关代码；定位指令扩展为条目级与字段级
- `frontend/src/components/ResumePreview.vue`：删掉 `#section-extra` 与 `#item-extra` 两个插槽
- `frontend/src/components/resume-editor.css`：删掉 `.paper-marker` 样式
- `frontend/src/components/CommentSidebar.vue`：顶部多一块结构问题清单；折叠态多一个计数
- `frontend/src/stores/draft.ts`：新增 `checkStructure()` 与最近一次检查结果的内存态
- `frontend/src/views/DraftView.vue`：保存时检查；有问题就留在编辑模式；侧栏接线与定位

**不受影响**

- 不改结构规则本身：规则、严重度、措辞一字不动
- 不改行内批注（诊断意见）的形态
- 不做实时的清单
- 不改诊断页与版本页
- 不新增依赖

**风险**

- 保存后不再自动切预览（有结构问题时）——这是本轮明确的行为变化，命令行快捷键与保存按钮走同一条路径
- 清单是快照，用户补完字段后清单不会立刻变短，要再保存一次才更新；标题写明「保存时发现的」以免误解
