## Context

上一轮把编辑能力补齐之后，纸面在编辑模式下暴露出四个排版问题。都出在"编辑控件沿用了组件库默认尺寸"和"编辑模式给所有分区都渲染同一套字段"上。

现在的条目头是一行 flex：

```
[公司][职位][时间]
```

三个字段在预览时是纯文本，在编辑时换成输入框与时间选择器。问题出在两处：

1. **宽度没有分工。** 文本块跟着内容走，输入框也是；但时间选择器是固定 220px 的组件，两个并排就把 680px 的内容区吃掉三分之二，公司与职位被挤到 100px 出头。
2. **字段的有无由"编辑模式"决定，而不是由"这个分区有没有这个字段"决定。** 代码里写的是 `v-if="item.org || editable"`——空了就渲染，为的是让新建的空条目也有框可填。专业技能分区本来就没有公司与职位，却也照画了一份。

## Goals / Non-Goals

**Goals:**

- 编辑模式下，公司与职位有足够的横向空间，时间字段不挤占它们
- 专业技能分区只出现技能行，不出现公司、职位与时间
- 专业技能的新增入口只有一个，且落在技能行上

**Non-Goals:**

- 不改领域模型与存储结构
- 不改预览模式与导出的版式
- 不做纸面版式的重新设计

## Decisions

### D1 宽度按角色分：内容字段弹性，时间字段固定

条目头在编辑模式下换一套排布：

```
公司或机构   flex: 1 1 0; min-width: 0
职位         flex: 1 1 0; min-width: 0
时间         flex: 0 0 auto; margin-left: auto
```

`flex: 1 1 0` 让公司与职位平分"内容区宽度减去时间块"之后的剩余空间，两栏一样宽——简历上公司名与职位名长度相近，等分比按内容分配更稳。`min-width: 0` 是必要的，否则长内容会把这一栏顶宽，另一栏被压扁。

时间选择器收到 88px：图标约 18px，`2021-03` 约 42px，加内边距刚好。两个选择器之间的空白从 40 多 px 收到 24px。

预览模式不动：预览里时间是右对齐的纯文本，`.paper-dates` 的 `margin-left: auto` 保持原样。

### D2 字段的有无由分区决定，不由编辑模式决定

把"有没有公司、职位、时间"从渲染条件里拆出来，交给分区：

```ts
function showFields(section: PreviewSection): boolean {
  return section.kind !== 'skills'
}
```

渲染条件从 `item.org || editable` 变成 `showFields(section) && (item.org || editable)`。空条目仍有框可填这个行为保留，只是不再套到没有这些字段的分区上。

### D3 技能的新增落在技能行上，不新建条目

技能在数据上是"一个条目里的一行行技能"（解析器就是这么分的），所以新增技能的正确做法是往这个条目里加一行，而不是新建条目——新建条目会造出一个只有公司/职位/时间的空壳。

```
专业技能
  · 前端：Vue、React、TypeScript
  · 新增的一条空技能行        ← 点「＋ 新增一条技能」得到的就是它
```

同时删掉技能条目末尾那条「＋ 新增一条要点」——分区末尾的「＋ 新增一条技能」已经能干这件事，两个按钮挨在一起是重复。

### D4 技能行的最后一条被清空后不留空条目

删掉或清空最后一条技能行后，那个条目就空了。空壳条目在纸上看得见，所以一并清掉。判断条件是"条目没有要点，也没有公司、职位、时间"。

## Risks / Trade-offs

**[两个时间选择器靠得近，选错月份的概率上升]** → 每个 88px 的框里只有一个年月值，不重叠；被选中时组件自己的高亮与弹层足够区分。

**[公司与职位等分宽度，短的公司名后面留白]** → 简历上这两栏本来就常一长一短，等分比"谁长谁宽"更稳定；输入框无边框，留白看起来是版式而不是空框。

**[专业技能分区没有条目级的删除按钮]** → 技能行本来就有自己的删除入口，逐行删即可；整块删掉专业技能不是常见动作。

## Migration Plan

1. `ResumePreview.vue` 加 `showFields` 与 `is-editable` 态的宽度规则
2. `DraftView.vue` 改新增落点、去掉重复入口、时间选择器宽度、清空壳
3. 验证：工作经历与项目经历的公司/职位宽度、时间块宽度、专业技能分区无输入框、新增技能的落点与焦点

**回滚**：纯前端改动，无数据迁移。
