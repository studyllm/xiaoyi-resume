## Context

简历编辑页（`frontend/src/views/DraftView.vue`）现在同时承担三件事：展示简历、摊开诊断意见、提示结构问题。三件事挤在一张纸上，于是纸既不是简历，也不是诊断报告。

现状上的三个具体矛盾：

1. **结构问题有两套实现。** `DraftView.vue` 里的 `structuralIssues` computed 自己实现了一遍"分区为空、缺机构名、缺职位类字段、缺开始时间、没要点"，`frontend/src/engines/diagnose.ts` 里又实现了一遍更全的结构规则。两者措辞不同、覆盖范围不同，横幅上的清单是引擎规则的子集。

2. **批注的正文流与规范相反。** `openspec/specs/resume-comment-anchoring/spec.md` 写着「批注 SHALL 展示在纸右侧的批注栏中，而不是插在内容之间」，但 `ResumePreview` 的三个插槽 `#section-extra` / `#item-extra` / `#bullet-extra` 往正文流里插了整张 `DiagnosisComment` 卡片。

3. **顺序在两个页面不一致。** `engines/diagnose.ts` 的排序是严重度优先，`engines/anchor.ts` 的 `orderByDocument` 是简历位置优先。诊断页用了后者，编辑页用了前者。

约束：`frontend/src/flows.spec.ts` 会扫描全部视图模板与样式文件——模板里不能出现内部术语「底稿」，样式里不能出现十六进制颜色字面量（只能用 `styles/tokens.css` 里的变量）。`frontend/src/engines/diagnose.spec.ts` 现有 502 行断言锁住了每条规则的 `ruleId`、严重度与文案，改造不能改动它们。

## Goals / Non-Goals

**Goals:**

- 结构问题只出现一次，且出现在它所指的位置旁边
- 纸面读起来是简历，诊断细节统一在右侧批注栏
- 界面上的批注一律按简历位置排列
- 纸面标注与诊断意见用同一套措辞，不出现两套叫法
- 页头在一行内说清"当前状态 + 下一步做什么"

**Non-Goals:**

- 不改诊断规则的判断口径、严重度与文案
- 不改预览模式版式、导出与版本生成
- 不给纸面标注做"点击直接聚焦到那个输入框"这类编辑焦点改造
- 不动批注栏的筛选与已处理/忽略机制

## Decisions

### D1 结构检查抽成独立模块，诊断与纸面共用

新增 `frontend/src/engines/structure.ts`，导出 `findStructureFindings(draft): StructureFinding[]` 与 `structureIssueId(ruleId, anchor)`。`diagnose.ts` 的结构类分支改为调用它，模板与 `missingOrgWords` / `missingTitleWords` 一并搬过去。

`StructureFinding` 同时带三份文案：`problem`（诊断意见的原话）、`suggestion`、`label`（纸面短标注，如「缺少开始时间」）。`label` 由 `SECTION_FIELD_WORDS` 派生，和 `problem` 出自同一份字段措辞表，所以「同一套说法」不是靠约定维持的，而是构造出来的。

**为什么不在视图里改一改横幅**：视图里那份实现已经在漂移，引擎多查了三条规则横幅都没有。横幅只做减法，下次引擎加规则还是会漏。

**为什么不把结构检查塞进 diagnose()**：纸面标注不能依赖"用户跑过诊断"。用户导入完直接进编辑页，还没诊断，结构标注也必须出现。`findStructureFindings` 是纯函数，直接吃 draft，与诊断结果无关。

### D2 结构标注贴在条目头与分区标题旁，只在编辑模式出现

条目级的问题（缺机构名、缺职位类字段、缺开始时间、没要点、时间倒序、时间重叠、结束早于开始）标在 `.paper-item-head` 内；分区级的问题（分区为空）标在 `.paper-section-title` 内。用插槽注入，纸上的其它视图不受影响。

标注长成一枚 chip：`⚠ 缺少开始时间`，无衬线字体（`--font-ui`）、11px、浅底色（`--severity-*-soft`）、圆角。**用无衬线是关键**：纸面正文是衬线体，标注换成无衬线，一眼能看出这不是简历内容。

只在编辑模式渲染。规范要求预览模式的简历上不出现任何标记，标注属于标记。预览模式仍然能在页头一行里看到结构问题的数量。

点击标注 → 用 `structureIssueId` 在诊断结果里找同名意见，找到就选中它，右侧批注栏高亮并滚到它；没跑过诊断就只是标注，不做别的事。

### D3 纸面批注改成轻量行内形式，完整批注留在右栏

要点下方保留一行摘要（`N 条批注 + 问题摘要`），展开后每条意见一行（严重度圆点 + 问题 + 建议），点击定位到右侧对应卡片。样式去掉卡片感：去掉底色与边框，只留左边一条 2px 的严重度竖线、12px 无衬线、`--ink-500` 文字。

摘要文案改用第一条意见的 `problem`。现在取的是 `highlight`（问题片段）或 `quote`（原句），那是"它批的是哪句话"，不是"问题是什么"。

右侧批注栏仍然是完整卡片：问题说明、改写建议、标记已处理、忽略。展开态的行内批注只承担"这句话有问题 + 大概怎么改"的速览。

**为什么不干脆把行内批注全删掉**：规范里「收起状态下仍能看到问题摘要」这条场景是有道理的——改一句话时，最该看见的是它有什么问题，而不是右栏第几条。摘要行解决这个问题，又不打断纸面。

### D4 批注顺序：引擎按严重度、界面按位置

`stores/draft.ts` 新增 `orderedIssues`（`orderByDocument`），编辑页与诊断页都用它。引擎内部仍然按严重度优先排序（`diagnose.spec.ts` 锁住了这个行为，且诊断结果本身需要先给严重问题），排序差异只发生在呈现层。

### D5 页头按"状态 → 模式 → 操作"分层

```
我的简历  [未保存]              [3 处结构问题 · 8 条诊断意见 去诊断] [预览|编辑] [保存] [放弃修改] [重新导入]
简历以这一份为准，改动不会影响已经生成的定向版本。
```

副标题从原来那句"我的简历是你唯一的事实来源……"压成一行。"事实来源"是内部说法，用户不会这么想；"重新导入简历（覆盖）"降级成最右边的文字按钮，覆盖警告仍然在确认弹窗里。

### D6 折叠态批注栏显示严重度分布

折叠成 56px 时，除了总数，还列出高/中/低三档的条数（未处理且未被忽略的）。点某一档 → 展开侧栏并把严重度筛选设为该档。数据从 `props.issues` 现算，不新增 store 状态。

### D7 删掉无人使用的状态与方法

`ui.ts` 的 `showLowSeverity`、`restoreIgnoredIssues`、`clearFocusComment`、`activeSection`、`clear()` 全仓无人读取或调用，一并删除；`focus()` 简化为只设 `focusedBulletId`。`expandedCommentIds` 一族保留——行内展开仍然靠它。

## Risks / Trade-offs

- **[诊断规则搬家可能改掉行为]** → `ruleId`、严重度、`problem` / `suggestion` 文案、id 构造、排序键全部照抄，`diagnose.spec.ts` 现有用例必须全绿；另加一条断言"诊断里的结构意见与 `findStructureFindings` 的 ruleId + 锚点完全一致"
- **[结构标注让纸面变脏]** → 标注只在编辑模式出现，且用无衬线 + 浅底色与正文区分；预览模式与导出里纸面是干净的
- **[行内批注展开后仍占纸面高度]** → 展开后每条一行、不带卡片边框，比现在的整张卡片省一半高度；若仍嫌挤，可后续改成默认收起且不自动展开（现在就是这样）
- **[纸面标注与右栏批注重复]** → 有意为之：纸面回答"哪里有问题"，右栏回答"怎么改"。两者用同一套措辞，不制造第二种说法
- **[改了 `uiStore.focus()` 的签名]** → 只有两处调用点（`DraftView.vue`、`DiagnosisView.vue`），一起改；`type-check` 会兜住漏掉的调用
- **[打印时纸面出现标注与行内批注]** → `ResumePreview` 的全局打印样式块里显式隐藏这两类元素

## Migration Plan

纯前端改造，无数据迁移。改动集中在结构规则的去处、编辑页模板与样式、批注栏与两个 store。回滚即还原这几个文件；OpenSpec 归档时同步主 spec。

## Open Questions

- 纸面标注点击后定位到右侧批注栏，是否要进一步直接聚焦到对应输入框（例如缺开始时间就聚焦到时间选择器）？本轮不做，涉及编辑焦点改造，留到下一轮。
- 结构标注是否需要在"改动后自动消失"上更主动？现在标注实时跟随 draft 重算，改完即消失，属于默认行为，不额外处理。
