## Context

P4 是「让引擎升级成 LLM，同时守住不编造」的阶段。12 人日的预算里，「LLM 适配器」只有 3 人日。

关键前提：**模型的输出不被信任。** 生成的内容要经事实账本与校验器判定之后才落库。「不编造」是这个产品的核心承诺，它不靠模型自己保证。

## Goals / Non-Goals

**Goals:**

- 定下模型接入的形态，让 P4 的 3 人日够用。
- 让「可审计」「可算钱」「可拦住」三件事落在我们自己库里。
- 不因为接入模型而在隐私面上多一层第三方。

**Non-Goals:**

- 不做多供应商路由（v1.0 只有一个供应商）。
- 不写 ADR-0003 的内容（事实账本与校验器规范，另写）。
- 不实现任何代码。

## Decisions

### D1. 「网关」拆成三个问题分别回答

接口问题（代码散落、错误处理不一致）→ 用接口解决。供应商路由问题 → v1.0 不存在。集中观测问题 → 我们自己做更准。

**理由**：不拆开就会为了一个不存在的问题（多供应商）付出一整套运维成本。

### D2. 不做独立网关进程，也不接托管网关

四条理由：人日不够且没地方加；网关日志接不上 P5 的 runbook 与泄露剧本，审计结论必须在我们自己的库里；托管网关多一层能看到简历正文的第三方；已经有一个自管 Postgres 要备份要监控了。

### D3. 规则与 LLM 做成同一接口的两个实现

`ResumeGenerator` 接口 + `rules` / `llm` 两个实现。回退是自然的（校验不过就用 `rules` 的结果），灰度对比是免费的（并排跑两个实现），换供应商是改一个文件。

**理由**：与 ADR-0001 的端口模式同源——视图与状态层不感知实现差异。P4 那 2 人日的「灰度对比与调优」因此不用额外搭一套对比框架。

### D4. 接口后面做四件事

生成日志、成本护栏、超时与重试、同输入缓存。全部落在 3 人日里。

**理由**：这四件事是「模型能被安全地接进来」的最小集合。少了生成日志就没有审计，少了成本护栏就没有预算控制，少了超时重试就一个抖动断一次。

### D5. 单供应商起步但接口不绑定

**理由**：中文改写效果在某个模型上不行是大概率事件。接口不出现供应商特有类型，换供应商才是一个文件的事。

**代价**：多供应商路由与 failover 将来要另做（写进「何时重开」）。

## Risks / Trade-offs

**[不做网关，多供应商要换供应商时会有阵痛]** → 接口已经把成本压到一个文件。供应商真出问题时的应急手段是回落 `rules`（功能不中断，质量下降）。

**[生成日志会存模型输出，等于把「可能编造的内容」也存了一份]** → 输出要存，否则审计无从谈起。但要控制两件事：输入用引用不复制正文；保留期比简历本身短（P5 的 data-retention 定）。

**[模型供应商的数据留存与训练条款会变]** → 上线前核对当前条款并写进 F8 的隐私结论，不凭印象写。

**[成本护栏的三个数现在还没定]** → P4 要定：单次输出 token 上限、每账号每日生成次数上限、每账号每日成本上限。超限时回落 `rules` 而不是报错。

## Migration Plan

无代码改动，无数据迁移。

## Open Questions

- 三个成本护栏的数值要按实际成本与产品定位定，P4 开工时算。
- 同输入缓存的失效策略：底稿改了、JD 改了、prompt 模板改了、模型换版本了——四种情况都该失效，具体规则在实现时定。
