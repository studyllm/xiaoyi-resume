## Context

`CLAUDE.md` §3.1 要求「颜色、字号、圆角、阴影、间距一律取自 CSS 变量」，但实际受约束的只有颜色——守卫扫的是 `#hex` / `rgb()` / `rgba()`。

尺寸是另一回事。**141 处写死的尺寸散在 22 个文件里**：字号、圆角、间距各有几十处 px，纸面另有 pt 与 mm。守卫里唯一查 px 的规则只扫落地页，注释里写着「存量其它组件还有八十余处写死的 px，不在本轮范围内，一起改会让这条守卫立刻失效，等于没有守卫」。

于是同一个「面板内边距 10px」，在落地页是变量、在批注栏是字面量。

## Goals / Non-Goals

**Goals:**

- 界面与纸面的尺寸全部走设计变量
- 守卫覆盖全量样式文件，不只是落地页
- 视觉位移可控、可枚举、可复核

**Non-Goals:**

- 不重新设计视觉——这次只改尺寸的**来源**，不改数值本身（离群值归并带来的 ≤4px 位移除外，且逐条列出）
- 不改几何尺寸（width / height / top / left / border-width / outline）——那些是布局结果，不是设计刻度
- 不动颜色相关的任何规则

## Decisions

### 决策 1：两套刻度，按用途分

| | 单位 | 变量前缀 | 为什么 |
| --- | --- | --- | --- |
| 界面 | px | `--space-*` / `--text-*` / `--radius-*` | 屏幕上的像素 |
| 纸面 | pt / mm | `--paper-text-*` / `--paper-space-*` | 纸面要打印，物理单位才对 |

守卫因此**只禁 px**：纸面的 pt 与 mm 是合法的物理尺寸表达。若把 `9.5pt` 折算成 px 再折算回去，会引入误差——纸面的字号就是按物理尺寸设计的。

### 决策 2：离群值就近归并，不单开变量

刻度上放不下的值（3、5、6、10、14px 等）归并到最近的刻度档，而不是给每个值单开一个变量——那会让「刻度」退化成「加了注释的魔数清单」，与这次收敛的目的相反。

代价是 45 处声明有位移（见下），其余 160 处精确映射、零变化。

### 决策 3：归并不许破坏既有的对齐关系

纸面要点的缩进是「列表 5mm + 条目 4mm = 9mm」，条目下的「＋ 新增一条要点」按钮正是靠 `margin-left: 9mm` 与要点文字对齐的。

第一轮归并把 5mm 改成 4mm、9mm 改成 10mm——**对齐断了，差 2mm**。这是本次实施里自己引入又修掉的一个回归。

因此为这两个值单独留档：`--paper-space-list: 5mm` 与 `--paper-space-indent: 9mm`，并在断言里把这层关系写出来。纸面页边距同理——横竖不同且是有意定的打印参数，拆成 `--paper-space-page-y` 与 `--paper-space-page-x` 保留原值。

### 决策 4：守卫按属性分级，不搞一刀切

守卫检查 `font-size`、`border-radius`、`padding`、`margin`、`gap` 及其长写形式，**不查几何尺寸**。理由：`width: 88px`（日期选择器）、`top: 12px`（定位）这类值是布局结果，与设计刻度无关；把它们也塞进刻度只会制造无意义的变量。

`border-width: 1px` 同理——发丝线不是刻度。

| --- | --- | --- |

## Risks / Trade-offs

- **位移会让某些地方看起来略有不同** → 全部列在上表，最大 4px。若某个具体位置不能接受，可单独把该值提回独立变量。
- **两套刻度增加了 token 数量**（78 → 97）→ 换来的是「界面用 px、纸面用物理单位」这条规则本身说得清。
- **守卫从只扫落地页变成扫全量** → 以后新增文件写死尺寸会立刻让 CI 变红。这是这次收敛的目的。

## Migration Plan

无数据迁移、无接口变更。只改样式来源，不改逻辑、DOM 结构与文案。

回滚策略：还原样式文件与 `tokens.css` 即可。
