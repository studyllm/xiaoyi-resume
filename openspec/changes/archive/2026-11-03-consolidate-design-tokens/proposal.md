## Why

`CLAUDE.md` §3.1 写着「颜色、字号、圆角、阴影、间距一律取自 CSS 变量」，但这条约束只真正落在**颜色**上——`flows.spec.ts` 的守卫扫的是 `#hex` / `rgb()` / `rgba()`。

尺寸是另一回事：**141 处写死的 px、pt、mm 散在 22 个文件里**，其中 106 处是字号、圆角与间距。守卫里唯一一条查 px 的规则只扫落地页，注释写得很直白：「存量其它组件还有八十余处写死的 px，不在本轮范围内，一起改会让这条守卫立刻失效，等于没有守卫。」

结果是：设计刻度散落各处，改一个间距要翻十几个文件；而且落地页已经严格、其它地方随意的状态本身就不一致——同一个「面板内边距 10px」在落地页是变量、在批注栏是字面量。

## What Changes

- **界面刻度收敛**：141 处 `font-size` / `border-radius` / `padding` / `margin` / `gap` 全部改为设计变量
- **纸面刻度独立**：纸面是打印稿，用 `pt` / `mm` 表达物理尺寸，界面刻度对它不适用——因此为纸面单独建一套 `--paper-*` 变量
- **守卫推广**：那条只扫落地页的 px 规则改成扫全量样式文件；只禁 px，纸面的 pt/mm 放行
- **视觉位移可控**：45 处声明的数值有变化（最大 4px / 1mm），其余 160 处是精确映射、零变化

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `product-visual-language`: 「界面样式只使用设计变量」这条要求补上尺寸类属性与纸面刻度的划分，并把守卫范围从落地页扩到全量样式文件。

## 关键决策

### 两套刻度，按用途分

界面层用 px 刻度，纸面层用 pt/mm 物理刻度。理由：纸面要打印，物理单位才是对的；把 `9.5pt` 折算成 px 再折算回去是引入误差。

守卫因此**只禁 px**：纸面的 pt/mm 是合法的物理尺寸表达。

### 离群值就近归并

刻度上放不下的值（3、5、6、10、14px 等）**归并到最近的刻度档**，而不是给每个值单开一个变量——那会让「刻度」退化成「加了注释的魔数清单」。代价是 48 处声明有 1–4px 的位移（界面）与 0.5–1mm 的位移（纸面）。

### 归并不能破坏既有的对齐关系

纸面要点的缩进是「列表 5mm + 条目 4mm = 9mm」，条目下的「＋ 新增一条要点」按钮正是靠 `margin-left: 9mm` 与要点文字对齐的。归并时把 5mm 改成 4mm、9mm 改成 10mm，**对齐就断了**。

因此为这两个值单独留了档：`--paper-space-list: 5mm` 与 `--paper-space-indent: 9mm`，并在断言里把「列表缩进 + 条目缩进 = 按钮缩进」这层关系写出来。

## Impact

- **样式**：`frontend/src/styles/tokens.css`（新增 17 个变量）、22 个组件与页面文件
- **守卫**：`frontend/src/flows.spec.ts`（px 规则从落地页扩到全量样式文件）
- **测试**：`frontend/src/components/ResumeEditor.spec.ts`（样式断言改读新位置，并新增对齐关系的断言）
