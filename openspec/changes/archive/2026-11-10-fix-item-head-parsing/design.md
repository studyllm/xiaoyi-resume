## Context

上一轮修掉了结构检查的两个假阳性与自动排序。用同一份 PDF 简历再跑，剩下的问题都出在「条目头怎么切」上：

```
【工作经历】
  org=项目经理 | title=Java高级开发 南京XXX信息科技有限公司 | 2022-04 → 2025-09
  org=Java高级开发工程师 | title=深圳XX信息技术股份有限公司 | 2020-09 → 2022-04
  org=项目组长 | title=南京XX科技有限公司 | 2017-09 → 2020-09
  org=Java开发工程师 | title=项目组长 南京XX数据系统股份有限公司 | 2013-03 → —
  org=— | title=— | 2017-09 → —
```

两件事：机构名与职位切反了；条目头被 PDF 的行宽切成两半，多出一条空条目。

## Goals / Non-Goals

**Goals:**

- 机构名与职位各归各位。
- 条目头被换行切断时，不多出条目。

**Non-Goals:**

- 不改条目时间的识别范围。
- 不处理表格（那张「其他项目经历」的表仍然被按列拆开）——下一轮。
- 不处理 PDF 把句子切成两半导致的要点碎裂（那是提取层的事）。

## Decisions

### D1. 机构名靠形态词认

机构名千奇百怪，形态词却很稳定：`有限公司`、`科技`、`集团`、`股份`、`信息技术`、`大学`…

条目头常写成「项目经理 / Java高级开发 | 南京XXX信息科技有限公司」——**职位并列在前，机构名在最后**。按分隔符切只能切出第一个片段当机构名，于是机构名与职位整体颠倒。

改成：切出来的片段里，**带形态词的那个是机构名，其余是职位**。没有形态词时保持原样（第一个片段是机构名）——大多数条目头本来就是「机构在前」。

形态词表覆盖公司类、学校类与金融机构类。带「数据」是因为「XX数据系统股份有限公司」这类写法很常见；带「中心」「事业部」是因为有些机构名就长这样。

### D2. 一行只有日期 → 补成上一条的结束日期

PDF 的行宽会把条目头切成两半：

```
Java开发工程师 | 南京XX数据系统股份有限公司 | 2013/03 –
2017/09
```

第二行除了日期没有别的字。它是上一条的**结束日期**，不是新的一条。

判据三条同时成立才合并：

1. 这一行除了日期没有别的字
2. 上一条有开始日期、还没有结束日期、也不是「至今」
3. 补上的结束日期**不早于**开始日期

第 3 条是必需的：表格里的行序不按时间走（那是表格，不是经历），补上的日期比开始还早时，说明它是下一行自己的日期。

## 验证方式

- `packages/shared/src/engines/parseDraft.spec.ts`：
  - 「项目经理 / Java高级开发 | 南京XXX信息科技有限公司」→ 机构名是南京XXX信息科技有限公司，职位是「项目经理 Java高级开发」
  - 条目头被切成两半 → 只有一条，结束日期是 2017-09
  - 补上的日期比开始还早 → 不合并
- **那份 PDF 当回归样本**：结构问题从 14 条降到 4 条，剩下的全部来自表格。
- 仓库根 `npm run verify` 全绿。
