## Why

产品已有 `docs/v0.1-产品需求文档.md` 定义的完整规则，但目前没有任何可运行产物：无法验证"一份底稿 + 多份 JD 快照"这条主流程在实际交互中是否成立，也无法在评审时演示底稿改写、版本差异、未覆盖要求这些关键行为。需要一个可点击走通全流程的前端原型，把 PRD 的规则外化成交互契约。

原型是后续实现的地基：规则在原型里被验证一次，实现阶段才不会被反复推翻。

## What Changes

- 新增 `frontend/` 目录，作为独立的前端原型工程（Vue 3 + TypeScript + Element Plus + Vite），与后端解耦、无后端依赖。
- 实现 7 个页面并串成一条可点击走通的主流程：登录 → 放入底稿 → 结构化编辑 → 诊断（可跳过）→ 粘贴 JD 生成版本 → 版本列表 → 版本详情（改动对照 / 未覆盖要求 / 复制正文）。
- 底稿以结构化内容保存（教育、经历、项目、技能），用户可直接改正文；再次放入内容时覆盖底稿，已生成的版本不受影响。
- 诊断只评价底稿本身，不读取 JD；每条意见锚定到具体句子并说明问题所在，不输出总分，不自动改写底稿。
- 按 JD 生成的版本是快照：只重组、删减、强调底稿中已存在的事实，不得新增公司、项目、职责或数字；底稿中无对应事实的 JD 要求，单独列出而非补写。
- 版本以"分区条目卡片对照"呈现相对底稿的改动（保留 / 改写 / 移至末尾 / 已移除），并可复制版本正文带走。
- 新增薄账号：一份可用登录方式即可；未登录不能保存任何内容。
- 界面全局标识"原型演示模式"，避免评审时把模拟输出误认为真实模型结果。
- **已知偏差**：PDF 上传在本原型中仅为占位，点击后提示原型阶段暂不支持解析并引导改用粘贴文本。PRD 验收标准中"PDF 能解析时得到可编辑底稿"因此不在原型覆盖范围内，后续实现阶段需补齐。

## Capabilities

### New Capabilities

- `account-access`: 薄账号登录、会话保持，以及"未登录不能保存底稿与版本"的访问约束。
- `resume-draft`: 放入底稿（粘贴纯文本 / PDF 上传占位）、解析为结构化可编辑内容、唯一底稿与覆盖语义。
- `draft-diagnosis`: 只针对底稿本身的诊断，产出锚定到具体句子的意见，覆盖"只有职责没有结果""表述空泛""时间线或结构不顺"三类问题。
- `jd-version-generation`: 依据粘贴的 JD 全文生成定向版本，含不编造约束、未覆盖要求的显式说明、版本命名与条目级改动记录。
- `version-management`: 多版本列表、版本详情（全文 / 改动对照 / 未覆盖要求）、正文复制、版本删除，以及版本与底稿的快照隔离语义。
- `prototype-runtime`: 原型自身的运行约束——无后端的本地模拟引擎、浏览器本地持久化、演示模式标识。

### Modified Capabilities

无。`openspec/specs/` 目前为空，本次为首次引入规格。

## Impact

- 新增目录 `frontend/`，含独立的 `package.json`、`vite.config.ts`、`tsconfig*.json`。
- 新增依赖：vue、vue-router、pinia、element-plus、@element-plus/icons-vue；开发依赖 vite、typescript、vue-tsc、@vitejs/plugin-vue。
- 不影响仓库中已有内容（`docs/`、`openspec/`）。
- 不引入后端、数据库或任何网络请求；所有数据保存在浏览器 localStorage。
- PRD 中"精美 PDF 导出""在线排版编辑器""多份底稿""题库与刷题"等明确排除项不进入原型。
