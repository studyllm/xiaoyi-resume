## Context

全项目 51 个操作按钮，形态五种、尺寸四档，没有任何规则在管。现状盘点：

| 形态 | 用例 | 数量 |
| --- | --- | --- |
| 实心主色 `type="primary"` | 所有页面的主操作 | 11 |
| 带边框（default） | 版本详情「复制」「返回列表」、JD 页「解析 JD」「载入示例」「查看已有版本」、对话框「放弃修改并离开」、落地页「直接看样例数据」、顶栏「导入简历」、打印条「返回」 | 8 |
| 文字 `text` | 编辑页「放弃修改」「重新导入」、诊断页「清空诊断结果」、导入页「载入演示数据」、版本卡片 4 个、批注卡片 3 个、对话框「留在本页」、删除确认组、侧栏折叠箭头 | 22 |
| 危险文字 `text type="danger"` | 纸面「确认删除？」×3 | 3 |
| 纯图标 | 垃圾桶 ×4、侧栏折叠箭头 ×2 | 6 |

四处具体的不一致：

1. **同语义不同尺寸**——编辑页页头 `primary size="small"`，其余所有页头主操作是默认尺寸。这是「保存和开始诊断长得不一样大」的根源。
2. **同层级两种外观**——诊断页「清空诊断结果」是文字，版本详情「复制」「返回列表」是带边框，JD 页「查看已有版本」是带边框。
3. **同类容器图标有无不同**——版本卡片行内动作全是「图标 + 文字」，批注卡片行内动作全是纯文字。
4. **导入页同屏两个实心主色**——「解析」（表单区）与「保存」（结果区页头），解析成功后同时可见。

另外两处是改动前就该说清楚的：

- 诊断页页头「开始诊断」与侧栏空状态「开始诊断」是**同一个动作出现两次**，两处都是实心主色。
- 编辑页页头的「去诊断」是 `el-link`，嵌在「还没有诊断结果 去诊断」这句话中间。

既有规格只规定了「删除入口统一用垃圾桶图标」与「主色与组件库一致」，没有规定按钮形态，所以本轮是新增一条要求而不是改写旧要求。

## Goals / Non-Goals

**Goals:**

- 次要动作在所有页面长得一样：文字按钮，hover 变主色。
- 按钮尺寸由动作区决定，同一个动作区里的按钮尺寸一致。
- 界面上至多一个实心主色。
- 同一张卡片内的行内动作形态一致。

**Non-Goals:**

- 不改任何按钮的行为与文案。
- 不改按钮的图标选型，只给批注卡片的「忽略此条」补一个图标。
- 不改纸面上的删除入口与删除确认组。
- 不改编辑页页头「去诊断」这个句子里的链接。
- 不动顶栏与落地页这两个全局上下文。
- 不引入新的按钮组件，继续用 `el-button`。

## Decisions

### 决策一：次要动作一律文字按钮，带边框只留两个例外

去掉「带边框的 default 按钮」作为通用次要动作形态，只保留：

| 例外 | 位置 | 理由 |
| --- | --- | --- |
| 落地页「直接看样例数据」 | `WelcomeView.vue` | 首屏两个并列 CTA，要能区分主次 |
| 对话框「放弃修改并离开」 | `UnsavedChangesDialog.vue` | 破坏性语义，要比旁边的「留在本页」醒目 |

顶栏的「导入简历 / 更换简历」不属于页面动作区，不在改造范围内。

### 决策二：尺寸按动作区划分，不按语义划分

| 动作区 | 尺寸 | 涉及按钮 |
| --- | --- | --- |
| 页面动作区（页头或页面末尾那排操作） | small | 诊断页、编辑页、版本列表、版本详情、导入页结果区、JD 页底部 |
| 页面级空状态 `el-empty` | default | 去导入简历、去粘贴 JD、回到版本列表 |
| 侧栏空状态 | small | 开始诊断 / 去诊断 |
| 卡片内行内 | small | 版本卡片、批注卡片 |
| 对话框 | default | 保存并离开 |
| 工具条 | small | 打印条、侧栏折叠箭头 |
| 落地页 | large | 放入第一份简历 |

**为什么空状态比动作区大**：空状态里按钮就是主角（页面上没有别的东西），动作区里按钮只是页头的一个配角。尺寸差异来自场景，不来自主次——这样「空状态的次要动作」和「动作区的主操作」不会因为语义不同而拿到同一个尺寸。

**为什么侧栏空状态用 small 而不是 default**：侧栏只有 320px 宽，32px 的按钮在里面显得笨重；更重要的是侧栏空状态的按钮与页头按钮指向**同一个动作**（开始诊断），两者尺寸一致才看得出是同一个动作。

### 决策三：JD 页底部的「生成版本」用 small

JD 页的动作排在页面末尾（那排不在页头），按「页面动作区 = small」的规则走。24px 的主 CTA 比现在弱一些，但这换来的是「所有页面动作区的按钮一样大」这条不用解释的规则。页面上方有 el-steps 承担流程感，底部按钮不需要再靠尺寸强调。

### 决策四：侧栏空状态的引导按钮降为文字按钮

诊断页页头与侧栏空状态都有「开始诊断」，同一个动作出现两次。两处都是实心主色就是同屏两块绿，而且用户会困惑这两块绿是不是一件事。

侧栏那个降为文字按钮，页头那个成为界面上唯一的实心主色。侧栏仍然保留这个入口——规格里「空状态提供发起诊断的入口」依然成立，只是入口的形态变了。

编辑页的侧栏空状态同理（「去诊断」），也用文字按钮。

### 决策五：编辑页页头的「去诊断」保留链接

它在「还没有诊断结果 去诊断」这句话中间，是**句子里的链接**，不是动作区里的按钮。`.draft-hint` 里有专门的对齐微调（`font-size: 12px; vertical-align: baseline`）。改成按钮要重调基线，而且句子被打断。

代价是同一个动作在编辑页（链接）和侧栏（按钮）长得不一样。取舍是：句子里的链接与动作区里的按钮本来就是两种模式，硬拉成一样反而更怪。

### 决策六：导入页保留两个实心主色

「解析」在表单区，「保存」在结果区页头，解析成功后同屏可见。它们是流程的两步、分属两个区域，不是同一个动作重复出现。

规则因此写成「同一个界面上至多一个实心主色，导入页是例外」，而不是「每个动作区至多一个」——后者太弱，挡不住诊断页页头与侧栏那两个绿。

### 决策七：批注卡片的三个动作都带图标

「去修改」已有 `EditPen`，「标记已处理 / 标记为未处理」已有 `Check` / `Close`，「忽略此条」补一个忽略图标（`Element Plus` 的 `CircleClose` 或 `Remove`）。

### 决策八：守卫测试放在 flows.spec.ts

`flows.spec.ts` 已经是这个项目的规范守卫（扫描样式字面量、组件库根包导入、界面禁用词）。按钮形态的规则放进同一处，扫描方式一致：

- `.page-actions` 与 `.import-actions` 块内的 `el-button` 必须都有 `size="small"`
- 动作区里实心主色按钮至多一个，导入页允许两个（规格写明的例外）
- 动作区里除实心主色外，其余按钮必须带 `text`
- 带边框的次要动作只允许出现在对话框、顶栏与落地页
- 每个界面上实心主色至多一个，登录卡与导入页白名单
- 版本卡片与批注卡片里的行内按钮必须带 `:icon`

### 决策九：过期告警条里的「重新诊断」降为文字按钮

诊断页的页头有「重新诊断」，简历被改过之后页面下方还会出现一条告警条，条里也有一个「重新诊断」。两个按钮做的是同一件事，原来都是实心主色。

按决策四的同一条原则（同一个动作不出现两次实心主色），告警条里的那个降为文字按钮，页头那个保留实心主色。告警条本身有警示色底，已经足够醒目，不需要按钮再强调一次。

### 决策十：导入页表单里的「解析」也用 small

导入页解析成功后，「解析」（表单区）与「保存」（结果区页头）会同屏出现。两者原本一个是 32px、一个是 24px——正是这一轮要消灭的那类不一致。

表单里的那排操作也是页面动作区（决策二里已经明确包括），所以「解析」「载入演示数据」都改成 small。这样导入页从表单到结果区一路都是 24px，只剩空状态里的引导按钮是 32px。

## Risks / Trade-offs

- **带边框的 default 按钮从项目里基本消失** → 顶栏的「导入简历」还留着，落地页和对话框也留着。所以「带边框」这个形态仍然存在，只是不再是通用的次要动作形态。
- **JD 页底部的「生成版本」变小** → 该页的主要动作视觉重量下降。换来的是全局一致的尺寸规则。
- **侧栏空状态的按钮变弱** → 在诊断页首屏，右侧栏的引导不如页头显眼了。但页头那个是实心主色，注意力没有被削弱。
- **守卫测试里的白名单会随新页面而增长** → 新增页面时若需要第二个实心主色，要在白名单里显式登记，而不是悄悄绕过测试。
- **按钮变小后点击区域变小** → small 的 Element Plus 按钮高度 24px，比默认的 32px 小。桌面上没问题，触屏上偏小。本项目是原型，没有触屏场景。
