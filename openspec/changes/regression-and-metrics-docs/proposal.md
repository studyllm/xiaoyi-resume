## Why

P2 的最后两项是两份不写代码的交付物，但它们决定了后面两个阶段能不能验收：

- **回归用例库**（T2.7 / 计划 D8）：现在 500 多个自动化用例覆盖不到 CSS 效果、版式、悬停反馈、PDF 文字层。人工验收每次都靠人临时想「该看什么」，发布检查单（P5 的 D10）要拿它当底稿。
- **成功指标口径**（T2.8 / 计划 D3、F6）：产品目前**完全没有指标定义**——连「用户在哪一步流失最多」都说不出来。P5 要补埋点与看板，届时再定口径，历史数据就不可比、看板要重做。

两份都是纯文档，但都不该拖到 P5：口径要提前冻结，回归清单要在 P3、P4 的改动里就开始用。

## What Changes

- 新增 `docs/regression-cases.md`：把自动化用例覆盖不到的部分整理成可勾选的人工验收清单——黄金路径、边界、空态与错误态、键盘流、打印稿、四档断点。
- 新增 `docs/success-metrics.md`：北极星指标、漏斗定义、每一步的流失口径、埋点事件表与属性。**只定义口径，不实现埋点。**
- 两份文档都不改动任何代码与能力域的 REQUIREMENT。
