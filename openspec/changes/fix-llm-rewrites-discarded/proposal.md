# 模型的改写被整批丢掉：查依据的编号对不上，实词比对的两边口径不一致

- 重量：重
- 澄清文档：无（bug 流程）
- 系统设计：无（bug 流程）

## Why

生成一版之后，界面说「模型这次没有用上，这一版由规则引擎生成」，改动对照里简历原文和版本文本**几乎一模一样**——用户看不出这一版到底优化了什么。

定位到的根因有三条，都不在界面上：

1. **模型给的子句编号是全局连续的**。提示词里每条要点下面都写着「子句 1、子句 2」，模型把编号当成了整份提示词里连续排下去的：给「要点 4」的是子句 `[4,5,6,7]`，而这条要点自己只有两三个子句。校验器按这条要点自己的事实去查，查不到 → 判成「模型没有指出它依据了哪些事实」→ **每一条改写都被丢掉**，整版回落规则引擎。用真实模型跑一遍，15 条改写全部被拒。

2. **实词比对的两边口径不一致**。被改写的那句先去掉评级词与动词再切实词，底稿那边的实词却是**没去**的。于是「支持多部门联合演练」在模型那边成了「多部门演练」，在底稿那边还是「支持多部门联合演练」——**同一个词，两边对不上**，判成「出现了底稿里没有的词」。这条同时打中规则路径：用户那份简历里有 2 条要点在规则路径上也被判了异常，措辞规范化被退回原文。

3. **模型写的正文与规则写的正文排版不一致**。模型写的句子带句末句号，规则写的句子不带（规则路径会去掉），同一份版本里两套排版，导出的 PDF 一眼能看出来。

**这三条都不是「模型不好用」**——是系统自己的比对口径有毛病，导致模型的产出被整批丢掉。而用户看到的现象是「优化在哪里」，也就是这个产品最核心的价值没有被交付。

**为什么现在才发现**：上一轮实现「把生成这一步拆开」时，验证用的是一份 5 条要点的合成简历，只看了流程通不通、数字对不对，没有用真实简历看改写的内容。这次拿用户那份 77 条要点的真实简历跑，才看见模型的产出全部被丢掉。

## What Changes

- **提示词**：子句编号的归属说清楚——「本要点的子句 N」，系统提示里写明编号在每条要点内从 1 开始，不要跨要点累加。这是根因的第一道修复：让模型一开始就算对。
- **校验器**：模型给的编号在**这条要点里查不到、但在这次发出去的事实里查得到**（说明它只是编号排错了）时，改用这条要点自己的全部事实复核，并记一条观察；编号比这次的事实总数还大（说明是编的）时，照旧丢掉。「模型引用了不存在的事实被换回」这条既有行为不变。
- **实词比对的两边口径对齐**：底稿的实词也去掉评级词与动词再切实词，比的是内容词。动词与评级各有自己的强度规则，不受影响。
- **模型正文的排版对齐规则路径**：去项目符号、统一半角与技术词大小写、整理空格、去掉句末标点。**不动词、不动语序**。
- **服务端 `LLM_MAX_TOKENS` 的默认值**：从 2000 提到 32000。2000 是单次问答的量级，一整版简历的改写量是它的十几倍——只配了供应商地址与密钥、忘了调这个值的人，第一次生成就会撞上截断（`server/.env.example` 里早就写着实测要 32000）。

**不改**：事实账本的校验规则本身（数字、实体、评级、动词的判定一个字不改）；「模型引用了不存在的事实要换回」这条行为；不新增错误码；不改接口。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `llm-engine`: 「模型改写后的正文过禁用词检查」之前补一条——**模型的改写要真的被采用**。现在补上「模型给的依据编号指向别处时，改用这条要点自己的全部事实复核」与「实词比对的两边口径一致」，以及「模型正文的排版与规则路径一致」。
- `jd-version-generation`: 「只重组、删减、强调底稿中已有的事实」补一条——规则路径校验实词时，底稿与改写正文**用同一套口径**去掉评级词与动词。

## Impact

**共享包**（`packages/shared`，前后端引用同一份）

- `src/engines/llmPrompt.ts`：系统提示第 6 条与每条要点的子句行。
- `src/engines/generator.ts`：编号对不上时的复核口径与观察记录；模型正文先做排版对齐再进校验。
- `src/engines/ledger.ts`：`draftTermsOf` 与 `extractComponents` 用同一个去动词/评级的函数。
- `src/engines/transforms.ts`：新增 `normalizeModelText`（中性排版处理）。

**服务端**

- `src/llm/config.ts`：`DEFAULT_MAX_TOKENS` 2000 → 32000。

**文档**

- `server/.env.example`：把「只配三个变量就会撞上截断」这一点写清楚。

**冻结点**

- **F4（事实账本 / 声明账本 / 校验器规范）**：形式上碰到了——`ledger.ts` 改了。改的是**比对时两边用的词表怎么算**（都去掉评级与动词），不是校验规则：数字、实体、评级、动词的判定与「不通过就换回」的语义一字不改。详见 design.md §Decisions。
- 其余冻结点（F1/F2/F3/F5/F6/F7/F8/F9/F10）不撞：不改接口、不改错误码、不改数据库、不改引擎异步语义。
