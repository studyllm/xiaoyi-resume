# 小奕 v0.1 产品需求文档

> **术语对照**：本文档用「底稿」指代用户持续维护的唯一事实源，用「版本」指代按某份 JD 生成的快照。
> 界面上它们分别显示为「**我的简历**」与「**多 JD 版本**」。本文档保留内部术语是为了让定义保持精确。

## 1. 背景

小奕的长期方向是八股文刷题。v0.1 只做简历，不做出题、题库或刷题，也不为以后的题目预留交互或文案。

求职者通常用多份 PDF 应对不同岗位，内容来自同一段经历，差别只是侧重点。v0.1 把这件事收成：一份事实底稿，按 JD 派生出互不影响的版本。

## 2. 目标

用户放入一份简历作为底稿，可以先看这份稿本身的问题，再粘贴一份 JD，得到一版针对该岗位的简历。底稿保留，每个 JD 对应一版可再次打开的快照。

## 3. 用户

正在投递技术岗位、手里已有一份简历的求职者。一个人对应一份底稿。中英文分稿、转行后事实集合分叉，不在本版考虑。

## 4. 范围

| 在本版 | 不在本版 |
|---|---|
| 放入一份底稿（粘贴或上传） | 八股题库、刷题、模拟面试，以及任何「会被追问」类诊断 |
| 不看 JD 的简历诊断 | 抓取招聘网站链接 |
| 粘贴 JD，生成一版定向简历 | 编造底稿中不存在的项目、公司、指标 |
| 底稿保留，按 JD 保留多个独立版本 | 多份底稿、简历库 |
| 薄账号，稿子跟着用户走 | 个人设置页、协作、模板市场 |
| 预览简历并导出可投用的 A4 PDF | 精美排版、模板市场、双栏版式 |
| 复制纯文本、复制为 Markdown、导出 PDF | 还原原 PDF 栏位与版式 |

## 5. 概念

```
用户
 └── 底稿（唯一，事实来源）
      ├── 抬头（姓名、定位、联系方式）
      ├── 教育 / 经历 / 项目 / 技能
      ├── 版本 · 某 JD（生成时的快照）
      ├── 版本 · 另一 JD
      └── …
```

- **底稿**：用户的事实源。抬头、经历、项目、教育、技能以可编辑的结构化内容保存，而不是一份不可改的文件。
- **抬头**：简历开头的姓名、一句话定位与联系方式。它和分区一样是事实，放进底稿，导出时印在页面顶部。
- **版本**：针对一份 JD、从当时的底稿生成的简历。生成之后独立保存，不随底稿后续修改而变化。
- **JD**：用户粘贴的职位描述全文。每个版本记住自己对应的 JD，便于再次打开时知道这版投的是什么。

底稿之后被用户改过，已有版本仍是生成当日的内容。要反映新底稿，就再生成一版。

## 6. 主流程

1. 用户登录。
2. 粘贴简历正文，或上传文件。系统整理成可编辑的底稿。
3. 用户可先做一次诊断（可跳过）。
4. 用户粘贴一份 JD，系统生成一个新版本。底稿不变。
5. 用户在版本列表中再次打开某一版，复制正文。

诊断不阻断第 4 步。没有底稿时，不能诊断，也不能生成版本。

## 7. 功能需求

### 7.1 放入底稿

- 支持粘贴纯文本。这是保证能用的路径。
- 支持上传 PDF。系统尽力解析成文本；解析失败或结果明显不可用时，把已得到的文本交给用户修改，不要求用户重新整理版式。
- 不支持 Word、图片、在线表格。
- 不承诺还原原文件的栏位、图标和分页。
- 一个用户同时只有一份底稿。再次放入时，覆盖底稿内容；已生成的版本不跟着改。
- 底稿保存为可编辑结构，至少包含：教育、经历、项目、技能。用户能直接改正文。

### 7.2 诊断

- 只评价底稿本身，不读取 JD。
- 结论要落到具体句子，并说明问题是什么。
- 诊断以「简历 + 批注栏」呈现：左侧是简历的只读排版，右侧是批注。每条意见作为批注挂在它所针对的位置旁边——句子里的意见挂在那句话的问题片段上，条目与分区层面的意见挂在对应的标题行上。点批注高亮简历中的对应文字，点简历中的文字高亮对应的批注。
- 批注按简历中出现的先后顺序排列，严重度用颜色区分；批注栏可折叠。
- 在底稿编辑页，每条有问题的要点旁同样展示它的批注，改的时候建议就在眼前。
- 本版关注的问题包括：只有职责、没有结果；表述空泛；时间线或结构明显不顺。
- 不输出单独的总分来代替上述意见。
- 不出现题目、考点或「面试会怎么问」。
- 诊断不自动改写底稿。用户自行决定是否修改。

### 7.3 按 JD 优化

- 输入是用户粘贴的 JD 全文，加上当前底稿。
- 输出是一个新版本，底稿保持不动。
- 只重组、删减和强调底稿里已经存在的事实，可以调整措辞使结果更清楚。
- 不得新增底稿中不存在的公司、项目、职责或数字。材料不足以支撑 JD 中的某项要求时，保持原样，并在该版本上说明哪些要求没有对应事实。
- 版本需要能看出相对底稿改了哪些条目。
- 版本名称默认取自 JD 中可识别的岗位名称；识别不到时，用用户可改的默认名。

### 7.4 多版本

- 版本列表展示底稿入口，以及全部已生成版本。
- 每个版本展示名称、对应 JD、生成时间。
- 打开版本后可以阅读全文、对照改动、复制正文。
- 版本是快照。底稿后续修改不回写旧版本。
- 同一份 JD 可以再次生成，产生另一份快照，不覆盖上一份。
- 用户可以删除某个版本。删除版本不影响底稿。

### 7.5 预览简历与导出

- 打开任一版本，可以预览它排成 A4 简历后的样子，也可以把它带走。
- **预览**：整页居中呈现一张 A4 纸，所见即所得——导出结果与预览一致。排版层级限定为单栏的经典简历形态：分区标题加粗带下划线、条目头「公司名 职位 …… 起止日期」两端对齐、要点悬挂缩进。不做双栏、侧边色块、头像与图标。
- **导出 PDF**：通过浏览器的打印能力导出，得到的 PDF 必须带文字层——简历要投给招聘管理系统，整页是图片的话对方提取不到任何字段。导出时界面自身的元素（顶栏、菜单、演示模式标识、按钮）一律不进入 PDF。
- **复制为 Markdown**：把版本按 Markdown 结构复制，便于投进接受 Markdown 的表单。
- **纯文本、Markdown、PDF 三种格式的内容一致**，分区、条目、要点与日期表示相同，日期统一写成 `2021-03`。
- 抬头从简历正文头部提取，也可以手动改。抬头缺失时导出前会提示。
- 版本携带生成时刻的抬头，之后改底稿不回写旧版本。
- 导出物不加页码与页眉页脚。
- 本版不做：精美排版、模板市场、双栏版式、还原原 PDF 栏位与版式（系统自始至终只拿到文本，原始版式既拿不到也拿不回，能做的只有生成一份新的标准排版）。

### 7.6 账号

- 底稿和版本必须归属于登录用户。未登录不能保存。
- 登录只解决「稿子跟着这个人」。本版不做资料设置、多设备以外的额外账号能力。
- 登录方式实现时再定，产品上要求一种可用的登录即可。

## 8. 规则

1. **一份底稿。** 不同岗位的差异用版本表达，不用多份底稿表达。
2. **快照。** 版本一旦生成即独立。更新内容的方式是重新生成。
3. **不编造。** 优化不得发明用户没有写过的事实。
4. **诊断与优化分开。** 诊断不看 JD；看 JD 的路径只有「生成版本」。
5. **与题目无关。** 本版界面、诊断文案和版本说明都不提及刷题或考点。

## 9. 验收

- 新用户登录后可以粘贴一份简历，得到可编辑底稿。
- PDF 能解析时得到可编辑底稿；不能解析时，用户仍能在文本上改完并保存。
- 对底稿诊断时，能看到指向具体句子的意见；诊断过程不要求填写 JD。
- 诊断以简历加批注栏呈现，批注挂在它批评的文字旁边，两侧可互相高亮。
- 粘贴一份 JD 后得到新版本，底稿原文仍在，且该版本标出了改动。
- 生成版本不会写出底稿中不存在的公司、项目或数字。
- 修改底稿后，此前的版本内容不变。
- 同一用户可保留多个版本，离开后再登录仍能打开并复制正文。
- 打开任一版本能看到 A4 简历预览，导出结果与预览一致。
- 导出的 PDF 带文字层，包含姓名与联系方式，不含界面自身的元素。
- 简历可以按 Markdown 格式复制，与纯文本、PDF 的内容一致。
- 产品中不存在题目、题单或刷题入口。
