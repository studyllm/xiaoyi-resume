# ADR-0005：模型接入形态

- **状态**：已接受
- **日期**：2026-11-04
- **相关变更**：`llm-generator`（生成器端口、OpenAI 兼容客户端、生成日志与降级）

## 背景

P4 要接大模型。模型调用只能在服务端——密钥不能进浏览器包（ADR-0001 已把这条写死），而 ADR-0004 已经把引擎放到了服务端。

ADR-0004 同时预告了一件事：接了模型之后，引擎不再是纯规则引擎，而是「远端模型 + 服务端规则」的混合，`ResumeEngines` 可能要拆。

「**要不要做大模型网关**」这个问题本身是模糊的。「网关」这个词底下混着三个不同的问题：

| 问题 | 是不是网关的问题 |
| --- | --- |
| 调模型的代码散落在各处、错误处理各不相同 | **不是**——这是接口问题 |
| 多供应商路由、故障转移、负载均衡 | 是 |
| 集中日志、成本统计、配额 | 网关能做，我们自己也能做，而且更准 |

P4 的预算是 **12 人日**（账本 3、校验器 3、LLM 适配器 3、灰度对比与调优 2、文档 1），其中「LLM 适配器」只有 3 人日。R1（LLM 编造）是全局风险登记里的极高等级项。

还有一个必须提前说清的前提：**模型的输出不被信任**。生成的内容要经过事实账本与校验器（F4、ADR-0003）判定之后才落库。「不编造」是这个产品的核心承诺，而它**不靠模型自己保证**。

## 决策

### 1. 不做独立的网关进程

不部署自建代理（one-api / LiteLLM 这类），也不接托管网关（云端 AI 网关、带面板的可观测平台）。理由四条：

**人日不够，而且加预算也没地方加。** 哪怕是开箱即用的自托管代理，也要部署、鉴权管理、监控、成本看板、故障演练，还多一个运行时依赖和一套 CI。P3 已经有一个自管的 Postgres 要备份、要监控、要演练升级了。

**网关帮不上「不编造」的忙。** 「这次生成了什么、校验结论是什么、能不能复现」必须落在**我们自己的库里**——那是 P5 的 `docs/ops/runbook.md` 和数据泄露剧本能管到的地方。网关的日志在别人那儿，我们的审计结论接不上。护栏指标「版本里的不实事实数」也不可能靠网关日志算出来。

**托管网关会多一层隐私面。** 简历正文要发给模型供应商，这一步躲不掉；再过一道托管网关，能看到请求体的第三方就从一家变成两家，F8 的隐私结论更难写。自建的代理不增加第三方，但增加运维面——同样不做。

**v1.0 只有一个供应商。** 网关的核心价值是多供应商路由。为不存在的问题写代码，是最贵的一种提前。

### 2. 把「网关」里真正有用的部分做成接口

规则引擎与 LLM 做成**同一个接口的两个实现**：

```
interface ResumeGenerator {
  generate(draft: Draft, jd: Jd, ctx: EngineContext, options: GenerateOptions): GenerationResult
}
```

| 实现 | 说明 |
| --- | --- |
| `rules` | 现在的 `generateVersion`，纯规则、可复现、零成本 |
| `llm` | 模型调用 + 校验；不合格时回落到 `rules` |

这样三件事同时成立：

- **回退是自然的**：LLM 输出没通过校验 → 用 `rules` 的结果。降级逻辑写在代码里，不在网关配置里。
- **灰度对比是免费的**：P4 那 2 人日的「灰度对比与调优」要并排跑规则版与模型版，同一个接口两个实现，直接跑。
- **换供应商是改一个文件**：中文改写效果在某个模型上不行是大概率事件（中文表达与「不编造」的判定都挑模型）。接口就是换供应商的缝。

这与 ADR-0001 的端口模式是同一套思路：**视图与状态层不感知实现差异。**

### 3. 接口后面做四件事

| 要做的 | 内容 | 为什么 |
| --- | --- | --- |
| **生成日志** | 输入引用、模型 id 与版本、prompt 模板版本、参数、输出、token 数、成本、校验结论、`integrity` 字段（F4） | 「输出可审计」的具体形态。R1 风险的追溯依据 |
| **成本护栏** | 单次生成的 token 上限、每账号每日生成次数上限、每账号每日成本上限 | 一次生成的花费要能算出来，也要能拦住 |
| **超时与重试** | 模型超时不能拖死请求；重试有上限，且不重复计费 | 弱网与模型抖动是常态，不是异常 |
| **同输入缓存** | 同一份简历 + 同一份 JD 再生成一次时命中缓存直接返回 | 简历工具场景下命中率不低；缓存键用输入哈希 |

这四件事**全部落在 P4 现有的 3 人日「LLM 适配器」里，不用加预算**。

**三个必须定下来的数**：单次生成的输出 token 上限（按产品能接受的最长那份简历估）、每账号每日生成次数上限、每账号每日成本上限。超限时回落到 `rules`，不是报错——用户要的是一份能投的简历。

### 4. 单供应商起步，但接口不绑定

供应商按计划假设「有可用的服务端调用通道与预算上限」来定。**接口里不出现供应商特有的类型。**

> **修订（2026-11-04，F8 之后）**：本文原先写「当前倾向 Anthropic」。**这条已被 `docs/privacy-conclusions.md` §4.3 推翻**——简历正文发给境外的模型服务构成个人信息出境，代价远超 v1.0 的承受能力。供应商范围收窄为**数据处理完全在境内**的服务商。接口与本 ADR 的其余部分不受影响。

上线前要核对两件事，写进 F8 的隐私结论：

- 该供应商当前的**数据留存**条款（保留多久、保留在哪）。
- 该供应商当前的**是否用于训练**条款。

这两条是会变的，不能凭印象写进隐私政策。

### 5. 生成日志落在我们自己的库里

新增表 `generations`，与 `drafts` / `versions` 同库（见 `docs/backend-stack.md` 的数据模型）。

日志里的**输出**字段要存——否则「审计」无从谈起。但要控制两件事：

- **不重复存简历正文**：输入用引用（`draft_id` + `revision`），不复制一份正文进日志。
- **保留期有限**：生成日志的保留期比简历本身短，具体数值在 P5 的 `docs/data-retention.md` 定。

## 何时重开这个决策

- **真的出现第二个供应商**，且需要在不改代码的情况下路由——中文效果、成本、可用性三者之一成为真实约束。
- **可用性要求自动 failover**：模型服务挂了要自动切到另一家。这需要网关，也需要我们自己做重试与退避。
- **企业客户要求走他们自己的网关**（BYOK / 私有部署）。
- **多个产品共用一套模型访问**，网关成为组织级基础设施。
- **要接的不只是文本生成**（例如嵌入、图像、语音），那时接口要重新划。

## 影响

- **ADR-0003（`integrity-verifier`）是另一半。** 0005 定「怎么调模型、要不要网关」，0003 定「事实账本与校验器怎么判」。**只有 0005 没有 0003，LLM 的输出就没有可信的落地路径**——R1 挡不住。两者要一起写。
- 新增能力域 `llm-engine`（P4）与 `fact-traceability`（P4）。
- 数据模型加一张 `generations` 表；`docs/backend-stack.md` 的数据模型一节要同步。
- `ResumeEngines` 的拆分方案（ADR-0004 提到的）落在这里：`ResumeGenerator` 是拆出来的那一半，`rules` 实现承接现有行为。
- P4 的 3 人日「LLM 适配器」覆盖第 3 节那四件事。**若还要做网关，预算要另加，且加在 P4 只有 12 人日的阶段里不现实**——那意味着砍别的。
- F4 的「回退语义」要写明：校验不通过时的行为是重试、回落到 `rules`、还是标记为不合格版本。本 ADR 定的是**回落到 `rules`**，具体规则在 ADR-0003。
