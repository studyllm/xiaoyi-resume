# ADR-0002：鉴权模型

- **状态**：已接受
- **日期**：2026-11-04
- **相关变更**：`p3-backend-foundation`（P3 开工前的设计输入）

## 背景

原型阶段的身份就是「一个名字」：`account-access` 规格明写「SHALL 只询问一个名字、SHALL NOT 要求密码」，`stores/session.ts` 里 `userIdOf(name)` 直接返回 `user-${name}`。这个形态没有密码、没有服务端、不跨设备。

P3 要把「本机 localStorage + 一个名字」换成真实账号与真实存储。届时 `account-access` **整域重写**（计划 T3.2），「无密码」这条要求退役（冻结点 F10 第 2 项）。

两个已定的前提：

- **账号形态**：计划 §7.5 的假设是「邮箱 + 密码」。
- **邮件服务商**：接。因此除登录外还要有邮箱验证与找回密码，比纯「邮箱 + 密码」多约 2 人日。

还有两条冻结点约束：

- **F5**：账号标识由服务端签发，必须不可猜测。不能再用 `user-${name}`——那等于把邮箱当主键，任何人都能猜。
- **F8**：隐私结论要在 P3 开工前定，其中必须覆盖「哪些数据入库、保留多久、是否发往第三方」。**用户邮箱会发给邮件服务商**，这是本 ADR 引入的新隐私面。

## 决策

### 1. 账号形态：邮箱 + 密码

密码用 **argon2id** 哈希存储。服务端不存明文，不存可逆密文，也没有「找回密码看密文」的路径——只有重置。

邮箱是登录标识。入库前做规范化（去空白、转小写），显示时用用户填的原样。

### 2. 注册流程：先建账号，再验证邮箱

```
填邮箱 + 密码 → 服务端建账号（状态：待验证）
                → 发验证邮件（带一次性签名链接，24 小时有效）
                → 用户点链接 → 账号激活
```

**待验证的账号不能登录，也不能保存简历或版本。**

但**导入页保持匿名可用**：未登录用户仍可以粘贴简历、解析、在纸上修改——这正是 `account-access` 现有规格里「导入页可以匿名使用」那条，重写时承接它而不是推翻它。用户是在看到解析结果之后才被问「要不要存下来」，那才是问身份的自然时机。

### 3. 找回密码：重置而不是找回

```
填邮箱 → 发重置邮件 → 点链接 → 设新密码 → 该账号的全部会话失效
```

**无论邮箱是否存在，界面的提示完全一样。** 提示不同等于泄露「这个邮箱注册过」，那是账号枚举。

### 4. 会话：服务端 session 表 + httpOnly cookie

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 凭据存放 | `httpOnly` + `Secure` + `SameSite=Lax` 的 cookie | 脚本读不到，XSS 偷不走 |
| 会话状态 | 服务端 session 表 | 能立即吊销、能「登出全清」 |
| 绝对有效期 | 30 天 | 到期必须重新登录 |
| 滑动续期 | 每次请求把到期时间往后推 | 活跃用户不被反复打断 |
| 登出 | 删服务端会话 + 清 cookie | |
| 「登出全清」 | 登出该账号的**全部**会话（计划 T3.2 要求） | 怀疑账号被盗时用户要能一次性清干净 |

### 5. 账号标识

`userId` 由服务端签发（`crypto.randomUUID()`），**不可猜测、不含邮箱、不从邮箱推导**。它是对外暴露的唯一标识；邮箱只用于登录与发信。

旧本地存档的 key（`user-${name}` 形式）在迁移时按名字匹配到服务端账号——映射规则属于 T3.8 的一部分。

### 6. 邮件服务商：接

选型判据，按重要性：

1. **送达率到中文邮箱**。目标用户是中文求职者，邮箱大多是 163 / QQ / 126。境外服务商发到这些邮箱的送达率普遍不好；反过来国内服务商在境外用户上更差。
2. SPF / DKIM / DMARC 三条 DNS 记录要能配齐——不配齐直接进垃圾箱。
3. 投递结果可查（成功 / 失败 / 退信），否则用户说「没收到」时我们无从判断是没发还是被拦。
4. 数据出境与留存说明要能写进隐私政策。

**默认：阿里云邮件推送**（按「用户主要在国内」这个前提）。若上线前确认用户主要在海外，改用 Resend。

发信记录要留：收件人、模板、时间、结果。**验证码与重置令牌只存哈希，不存明文。**

### 7. v1.0 不做的事

第三方登录、短信验证码、手机号验证、多因素认证、账号注销的即时生效（注销流程 P5 再定）。

## 何时重开这个决策

- 用户量上来后需要「邮箱和密码都换了」的账号找回——那是一条客服流程，不是自助流程。
- 目标市场从国内转向海外（换邮件服务商）。
- 要接第三方登录或企业 SSO。
- 监管要求对「账号可携带性」有更明确的规定。

## 影响

- `account-access` **整域重写**（T3.2）；「无密码」要求退役（F10 第 2 项），以该阶段首个实现变更的 delta spec 形式提出。
- 新增能力域 `server-api` 的鉴权部分；`docs/api-contract.md` 的鉴权一节按本文写。
- **F8 的隐私结论必须覆盖邮件服务商**：用户邮箱会发给第三方，这一点要写进 `docs/privacy-policy.md`（P5）与数据留存口径。
- 验证邮件与重置邮件的文案进 `docs/error-taxonomy.md` 的状态表——「没收到验证邮件」要有明确出路（重发、换邮箱、稍后再试）。
- 工期：P3 由 12 人日增至 **14 人日**（计划 §7.5 已预留「邮箱验证另加约 2 人日」）。
- 邮件服务商是 P3 引入的**第一个外部供应商依赖**，也是唯一会直接接触 PII 的一个。
