# 响应式断点与无障碍基线

这份文档定下界面在不同屏幕宽度下的行为契约，以及无障碍的四条底线。

- **实现在哪**：`frontend/src/domain/breakpoints.ts`（分档纯函数）、`frontend/src/composables/useViewport.ts`（唯一的尺寸监听点）、`frontend/src/composables/usePaperScale.ts`（纸面缩放）、`frontend/src/components/PaperCanvas.vue`（缩放与状态播报）。
- **范围**：只做「不破版 + 明确降级」。**不做移动端专属布局**，完整 WCAG 审计列入 v1.1。

---

## 1. 四档断点

| 档位 | 视口宽度 | 应用侧栏 | 纸面 | 工作台 |
| --- | --- | --- | --- | --- |
| 宽屏 | ≥ 1440 | 常驻 200px | 原尺寸 | 正常渲染 |
| 窄屏 | 1024–1439 | 常驻 200px | 按可用宽度等比缩放 | 正常渲染 |
| 紧凑 | 768–1023 | 收成抽屉 | 按可用宽度等比缩放 | 正常渲染 |
| 屏幕过小 | < 768 | 收成抽屉 | 不渲染 | 只给降级提示 |

分界值是 `domain/breakpoints.ts` 里的常量。**视图不自己比数字**——改一个分界只改一处。

```ts
export function tierFor(width: number): ViewportTier
export function usesDrawer(tier: ViewportTier): boolean
export function rendersWorkbench(tier: ViewportTier): boolean
```

## 2. 各档的具体行为

### 2.1 侧栏抽屉（< 1024）

侧栏收成**覆盖式抽屉**：固定在左侧、盖在内容之上，不占内容区的宽度。

- 顶栏出现「导航」按钮，点它唤出或收起抽屉。
- 点遮罩、点导航项、按 `Esc` 都收起抽屉。
- 抽屉关闭时带 `inert`，键盘不会误进到看不见的菜单里。
- 抽屉自身 `overflow-y: auto`，菜单长的时候在抽屉里滚。

**为什么是覆盖而不是推挤**：推挤会让正在看的纸面跳位置。编辑中的用户一旦失去上下文，就不知道自己刚才改到哪了。

### 2.2 纸面等比缩放

纸面自然宽度是 210mm（约 794px）。容器不够宽时按比例缩小：

```
缩放比例 = clamp(容器可用宽度 / 794, 0.7, 1)
```

- 量的是**没有缩放的容器**——缩放过的元素量出来的是缩放后的尺寸，拿它去除会越算越小。
- **下限 0.7**：低于这个比例正文已经小到读不了。那种宽度下宁可让内容横向滚动，也不给一份看不清的纸面。
- 用的是 `zoom` 而不是 `transform: scale()`：`transform` 不改变布局盒，缩放后的纸面在容器里仍占 794px，容器照样溢出；`zoom` 会重排，容器的宽高跟着变。
- **打印稿不受影响**：打印样式里把 `zoom` 复位成 1，导出仍是 A4 原尺寸。

### 2.3 屏幕过小时（< 768）

工作台整块不渲染，换成一块降级提示：

> **请在更大的屏幕上使用**
> 这份简历要在一张 A4 纸上编辑和对照，手机屏幕放不下。把窗口拉宽到 768 像素以上，或者换一台屏幕更宽的电脑。

**为什么不给一个半残的编辑器**：读一份简历在手机上可行，**编辑**一份简历不可行。与其让用户在一个挤扁的界面里操作，不如明确说清为什么不行。

## 3. 无障碍的四条基线

| 基线 | 做法 | 守在哪 |
| --- | --- | --- |
| 图标按钮有可访问名称 | 只有图标的按钮一律带 `aria-label` | `flows.spec.ts` 守卫 |
| 焦点始终可见 | 全局 `:focus-visible` 焦点环 | 浏览器验收 |
| 状态向读屏软件播报 | 纸面区域是 `role="region"`，另有一个 `aria-live="polite"` 的状态行 | 浏览器验收 |
| 尊重减少动效 | `prefers-reduced-motion` 下关闭过渡与动画 | 浏览器验收 |

### 3.1 焦点环

用 `outline` 而不是 `box-shadow`——纸面上的输入框各有自己的聚焦样式，`outline` 叠在上面不会覆盖它们。

`:focus-visible` 只在键盘操作时出现，鼠标点击不显示。这是浏览器的既定行为，也符合「键盘焦点必须始终可见」的要求：鼠标点击本来就不需要焦点环。

### 3.2 状态播报

纸面区域带 `role="region"` 与名字「简历正文」，读屏软件可以跳进去。区域里另有一个视觉上藏起来的 `aria-live="polite"` 状态行，播报：

- 「简历有未保存的修改」
- 「还没有诊断结果」
- 「诊断没有查出问题」
- 「简历已保存，共 N 条诊断意见」

用 `polite` 而不是 `assertive`：保存成功这种消息不需要打断读屏软件正在读的内容。

**注意**：状态行不在纸面内容里。纸面上的输入框每敲一个字都会变，把整个纸面设成活动区域会变成逐字朗读。

## 4. 已知限制

- **`zoom` 不是 W3C 标准**。Chrome 与 Safari 一直支持，Firefox 自 126（2024-05）起支持。更老的 Firefox 上纸面会横向溢出——不至于白屏，但版式会破。这是「原型面向现代浏览器」这个前提下的取舍。
- **缩放下限 0.7 是拍的**，没有实测过「在 550px 宽的纸上读正文」的舒适度。v1.0 上线后按真实反馈调。
- **抽屉的唤出按钮用文字「导航」而不是图标**。规范 §4.6 说工具条里的按钮是 small 尺寸，文字按钮在这个位置比图标更容易被读屏软件念出来。
- **完整 WCAG 审计不在本阶段**。这里只做基线：对比度、屏幕阅读器的完整走查、认知负荷都还没查。
