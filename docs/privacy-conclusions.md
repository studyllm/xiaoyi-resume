# 数据隐私口径结论（F8）

> **性质**：这是**产品侧结论**，不是隐私政策。隐私政策（`docs/privacy-policy.md`）与数据留存清单（`docs/data-retention.md`）在 P5 写，**照这份结论写**。结论不能后补——数据已经存了才决定保留策略，就撤不干净、注销做不到。

- **冻结点**：F8（`docs/产品开发计划-v1.0.md` §11）
- **冻结时点**：P3 开始前
- **状态**：产品结论已定，标 ⚠️ 的三处待法务确认

---

## 1. 数据分类

| 类别 | 内容 | 敏感度 |
| --- | --- | --- |
| **A 账号** | 邮箱、密码哈希（argon2id）、邮箱验证时间、`userId`（服务端签发的 UUID）、会话记录 | 低—中 |
| **B 简历底稿** | 抬头（姓名、电话、邮箱、地址）、教育/工作/项目/技能/其它的**全文** | **高**（个人职业信息） |
| **C 版本** | 由底稿派生的正文快照、JD 全文、改动对照、覆盖情况、`facts`/`claims`/`integrity`（ADR-0003 的 `trace` 段） | **高**（含 B 的内容） |
| **D 生成日志** | 模型 id 与版本、prompt 模板版本、参数、token 数、成本、**模型输出全文**、校验结论 | **高**（输出是简历内容） |
| **E 技术数据** | `session_id`、`event_id`、视口档位、请求 id、耗时、错误堆栈 | 低 |
| **F 邮件记录** | 收件地址、模板、时间、投递结果 | 低—中 |
| **G 备份** | 数据库快照，含 A–F 全部 | **最高** |

**「简历正文」是本产品唯一真正敏感的东西。** 它的全部副本——主库、备份、模型供应商、生成日志——都要被同等对待。

---

## 2. 入库与不入库

### 入库

A、B、C、D、F（各类的保留期见 §3）。

### 不入库

| 不入库 | 理由 |
| --- | --- |
| 密码明文 / 可逆密文 | 只有 argon2id 哈希。**没有找回密码看密文的路径**，只有重置 |
| 验证与重置令牌明文 | 只存哈希。令牌本体只在邮件链接里出现一次 |
| 简历正文的**内容日志** | 技术日志只记 id、耗时、结果。**正文不进日志**——日志通常被更广泛的人看到 |
| 第三方 SDK 的会话回传 | Sentry 之类的错误上报要在发送前脱敏 |

### 边界情况

| 情况 | 结论 |
| --- | --- |
| **本地缓存**（localStorage） | 迁移成功后**默认清除本地副本**，并提示。要保留必须用户明确勾选——本地副本是 PII 残留，留着就等于没迁 |
| **演示数据** | 是假数据，不涉及真实用户。但演示模式标识在 P6 移除前，界面必须说清「数据只在本机」 |
| **JD 全文** | 属 C 类，随版本存。用户删版本即删 |
| **模型供应商的训练使用** | 一律不允许。见 §4 的门槛 |

## 3. 保留期

**原则：最短必要。** 每类数据只保留到它自己不再有用的那一刻。

| 类别 | 保留期 | 到期后 |
| --- | --- | --- |
| 会话 | 绝对有效期 30 天，滑动续期 | 过期删除 |
| 验证 / 重置令牌 | **24 小时**，验证成功后立即删 | 删除 |
| 简历底稿（B）、版本（C） | 账号存续期间 | 用户删或注销时删 |
| 生成日志（D） | **90 天** | 删除。**比简历本身短**——它只需要支撑审计与成本核算 |
| 技术日志（E） | **30 天** | 删除 |
| 邮件记录（F） | **90 天**（投递排查） | 删除。**邮件正文不留存** |
| 错误上报（Sentry） | **90 天**，发送前脱敏 | 删除 |
| 备份（G） | 滚动：日备 7 份 + 周备 4 份 | 见 §6 的删除延迟窗口 |

## 4. 第三方接收方

**每一个接触简历内容的第三方都要单独列出来，写清发什么、留存多久、有什么合同保证。**

### 4.1 邮件服务商（阿里云邮件推送）

| 项 | 结论 |
| --- | --- |
| 发什么 | 用户的邮箱地址 + 验证/重置链接 |
| 不发什么 | 简历正文、姓名、任何附件 |
| 留存 | 我们侧记录 90 天（收件地址、模板、时间、结果）；**服务商侧的留存按其条款，签约时写死** |
| 合同保证 | 不用于自己的营销；处理范围仅限发送本服务的事务邮件 |

### 4.2 对象存储（备份）

| 项 | 结论 |
| --- | --- |
| 发什么 | 数据库快照——**含简历正文** |
| 留存 | 与备份周期一致 |
| 合同保证 | 加密存储、访问仅限运维账号、访问要留审计日志 |
| ⚠️ 待确认 | 存储区域与备份加密密钥的托管方式——**如果对象存储在境外，备份出境同样是个人信息出境**。要与 §4.3 用同一条规则 |

### 4.3 模型供应商（P4）

| 项 | 结论 |
| --- | --- |
| 发什么 | **生成所需的最小内容**：与目标岗位相关的分区 + 该份 JD。不发整份简历，不发姓名、电话、邮箱 |
| 留存 | 合同写死 ≤ 30 天，且**明确不用于训练** |
| 硬门槛 | ① **数据处理完全在中国境内**，或该供应商能提供满足个人信息出境要求的前提；② 合同写明不用于训练；③ 合同写明留存期限 |

### 4.4 一条推翻既有选型的结论

**模型供应商必须满足 §4.3 的三条硬门槛，第一条是硬的：数据处理完全在境内。**

理由：简历正文发给境外的模型服务，构成**个人信息出境**。这不只是多一份同意书——它要单独同意、要告知境外接收方、要评估法律路径，成本与不确定性都远超 v1.0 的承受能力。

**这条推翻了 `docs/adr/0005-llm-access-shape.md` 里「当前倾向 Anthropic」那一句。** 那份 ADR 写的时候还没有隐私结论；现在有了，供应商范围要收窄到境内服务商。

⚠️ **待法务确认**：个人信息出境的适用口径与所需前提。若法务认为境内处理的要求可由其他安排满足（例如服务商承诺数据不出境且出具书面保证），那么 §4.3 第一条可以放宽到「有合同保证的境内处理」。**在法务给出结论之前，按最保守的假设设计：只考虑境内服务商。**

### 4.5 错误上报与监控

Sentry 只收服务端异常与请求元数据，**发送前脱敏**（正文、邮箱、令牌一律替换）。Uptime 监控只发 ping。

## 5. 用户权利范围

| 权利 | 怎么做 | 边界 |
| --- | --- | --- |
| **知情** | 注册前明示：隐私政策 + 「简历正文会发给境内模型供应商用于生成版本」+ 单独同意 | 未勾选不能注册 |
| **查阅与复制** | 一键导出全部内容：简历（JSON）+ 每个版本（Markdown / PDF） | 导出物本身也是 PII，用户自己负责 |
| **更正** | 简历本来就可直接编辑，改完即生效 | — |
| **删除** | 单份版本可删；删全部即注销账号 | — |
| **撤回同意** | 撤回 = 注销账号。**v1.0 不提供「不用模型」的长期开关** | 见下方说明 |
| **注销** | 立即从主库删除简历、版本、生成日志、会话；**30 天内不可恢复**，之后不可找回 | 备份里的残留见 §6 |

### 5.1 为什么 v1.0 不给「不用模型」的开关

两个理由：

1. **它需要一个设置页**，而 §1.2 明确把「个人设置页、资料设置」排除在 v1.0 之外。
2. **规则引擎长期保留**（ADR-0002、§12.5），但它是**降级路径**（模型超时、拒答、校验不通过时用），不是「无模型模式」——保留它不等于要给用户一个开关。

**但「一次性选择」不需要设置页。** 生成版本页已经有「生成选项」这张卡（两个开关），加第三个开关「本次用规则引擎生成（不把简历发给模型）」几乎零成本，而且给了用户真实的拒绝权。

✅ **已定（2026-11-08，P4 实现时落定）**：**加这个开关，且默认关闭**——要发就得用户点头，不发是默认状态。接口契约里的 `options.useLlm` 默认 `false`。

理由：默认关闭是唯一「明示同意」的口径；默认打开即使带提示，也只是「告知 + 可拒绝」。代价是模型路径要用户主动打开，这与「规则引擎长期保留」的判断一致。

**我的建议是加。** 理由：它是「明示同意」之外的另一条腿——有选择权的同意比没有选择权的同意稳得多；成本是一个开关；而且它顺带给了「模型效果不如规则引擎时手动切换」的实用价值。

## 6. 备份里的删除延迟

**「删除」不可能是即时的。** 备份的存在就是为了恢复，删账号时立刻从备份里抹掉，等于放弃恢复能力。

**结论：注销后，主库立即删除；备份里的残留最多保留 30 天**，随滚动窗口自然消失。

- 30 天是滚动窗口的边界：**日备 7 份（约 7 天）+ 周备 4 份（约 28 天）**。
- 界面必须说清这一点：「注销后数据立即从服务器删除，备份中的残留最多 30 天后消失。」**不许说「立即删除」。**
- ⚠️ 待法务确认：30 天这个窗口是否满足「删除权」的合理期待。

| 落点 | 内容 |

| 注册页 | 隐私政策摘要 + **单独勾选**「我同意简历正文被发给境内模型供应商用于生成版本」 |

## 8. P5 要写什么（骨架）

这两份是**照本文件写的**，不是另起炉灶。

### `docs/privacy-policy.md`

1. 我们收集什么（§1 的分类表，用户能看懂的说法）
2. 收集哪些是必需、哪些是为了别的目的
3. **简历正文会被发给谁**（§4.3，境内模型供应商，含「不用于训练」的承诺）
4. 保留多久（§3）
5. 用户权利与怎么行使（§5）
6. **注销后备份残留 30 天**（§6）——不许含糊
7. 未成年人：产品面向求职者，不面向未成年人；发现误注册怎么处理
8. 联系方式与投诉渠道

### `docs/data-retention.md`

§3 的表格逐行展开，加上：每类数据的**删除触发点**（到期自动删 / 用户主动删 / 注销连带删）、以及**验证方式**（怎么证明真的删了）。
