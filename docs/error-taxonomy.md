# 状态与文案体系

用户看得见的每一次「没成」和每一次「还没有」，都应当说清现在的状态与下一步能做什么。这份文档登记产品里的全部状态，是界面文案的唯一来源。

- **实现在哪**：`frontend/src/domain/states.ts`——`FAILURE_STATES`（失败态）、`EMPTY_STATES`（空态）、`WARNING_STATES`（警告态）三张表。
- **怎么用**：视图不写失败与空态的字面文案，从表里取。消息提示用 `stateMessage(state)`，页面内告警用 `stateTitle(state)` + `stateHint(state)`，空态用 `EmptyState` 组件。
- **守在哪**：`frontend/src/flows.spec.ts` 的「状态与文案体系」一组用例。视图里出现失败与空态的说法，测试直接红。

---

## 1. 一条状态由三段组成

| 段 | 作用 | 用在哪 |
| --- | --- | --- |
| **标题** | 短句，只说明现在的状态 | 告警标题、空态标题 |
| **说明** | 一句话，讲清为什么是这个状态，以及用户现在能做什么 | 告警说明、空态说明、消息提示 |
| **主动作** | 用户点了就能改变这件事的动作 | 空态里的主按钮；没有可执行的下一步时不写 |

可变内容（数量、页数、MB）写成 `{value}` 占位符，取值时替换。整张表只允许这一个占位符名字——调用方只可能知道一个可变的量。

## 2. 失败态

失败态的共同要求：**说清没成什么，并且给出下一步**。只报「失败」不给路的写法一律不合格。

| 键 | 什么时候出现 | 标题 | 说明 |
| --- | --- | --- | --- |
| `parse-empty` | 粘贴框里没有正文 | 没有可解析的内容 | 先把简历正文粘贴进来，至少要有分区标题和条目。 |
| `parse-failed` | 文字里认不出简历结构 | 解析失败 | 没能从这段文字里认出简历结构，换一种带「教育背景」「工作经历」这类分区标题的写法再试一次。 |
| `save-failed` | 存简历没存成 | 保存失败 | 这次的结果没能存下来，重新解析一次再保存。 |
| `nothing-to-save` | 还没有解析结果就要保存 | 没有可保存的结果 | 先解析出简历内容，保存才可用。 |
| `jd-empty` | JD 框里没有正文 | 还没有 JD 全文 | 先把岗位描述完整地粘贴进来，系统才能提取出岗位要求。 |
| `jd-parse-failed` | JD 里认不出岗位要求 | JD 解析失败 | 没能从这段 JD 里认出岗位要求，检查是不是复制完整了，再试一次。 |
| `generate-no-draft` | 没有简历就要生成版本 | 需要先导入简历 | 还没有简历内容，导入一份简历再生成版本。 |
| `generate-failed` | 生成版本没成 | 生成失败 | 这次没能生成版本，重新生成一次。 |
| `copy-failed` | 剪贴板写不进去 | 复制失败 | 浏览器没有把正文写进剪贴板，手动选中正文复制。 |
| `draft-required` | 路由拦住了需要简历的页面 | 需要先导入简历 | 还没有简历内容，导入一份简历再继续。 |
| `demo-load-failed` | 演示数据没载进来 | 演示数据载入失败 | 刷新页面再试一次。 |
| `pdf-not-pdf` | 上传的文件不是 PDF | 这不是 PDF 文件 | 请上传 PDF，或改用「粘贴文本」。 |
| `pdf-too-large` | 文件超过 10 MB | 文件太大 | 这份文件超过 {value} MB，请压缩后再上传。 |
| `pdf-too-many-pages` | 文件超过 50 页 | 页数太多 | 这份文件有 {value} 页，超出可解析的上限，请只上传简历部分。 |
| `pdf-encrypted` | PDF 有打开口令 | PDF 有打开口令 | 请先去掉口令再上传。 |
| `pdf-corrupted` | 文件损坏或格式不受支持 | 文件读不出来 | 可能是文件损坏或格式不受支持，请换一个文件，或改用「粘贴文本」。 |
| `pdf-unreadable` | 其它读不出来的情况 | 这份 PDF 读不出来 | 请换一个文件，或改用「粘贴文本」。 |
| `pdf-engine-unavailable` | PDF 读取组件没加载起来 | PDF 读取组件加载失败 | 请刷新页面再试，或改用「粘贴文本」。 |
| `pdf-no-text-layer` | PDF 没有文字层（扫描件或图片页） | 这份 PDF 没有可读取的文字层 | 可能是扫描件或图片页，请改用「粘贴文本」，把内容贴进来。 |
| `export-missing-profile` | 导出时抬头缺姓名或联系方式 | 抬头缺失 | 这份简历还没有姓名与联系方式，导出的 PDF 不能直接投递；要导出的话，先回去补全抬头。 |
| `storage-unavailable` | 浏览器不让存本地数据 | 本地存储不可用 | 刷新后数据会丢失，这页先别继续操作。 |
| `not-logged-in` | 存简历时还没有身份 | 还没有登录 | 先登录，然后才能保存与同步。 |
| `confirm-overwrite` | 覆盖当前简历但还没确认 | 需要先确认覆盖 | 覆盖当前简历要先确认一次，已经生成的版本不会跟着改变。 |
| `network-failed` | **P3 占位**，服务端化之后才会触发 | 网络请求失败 | 检查网络连接后重试。 |

`network-failed` 现在还没有触发逻辑。提前把文案定下来，是为了 P3 不用再回头改一遍界面。

## 3. 空态

空态分三层：标题、说明、主动作。**没有主动作时，说明里必须讲清为什么没有**——不能放一个点了也没用的按钮。

| 键 | 什么时候出现 | 标题 | 说明 | 主动作 |
| --- | --- | --- | --- | --- |
| `no-draft` | 还没有简历 | 还没有简历 | 导入一份简历后，就能编辑、诊断，并按岗位生成版本。 | 去导入简历 |
| `no-versions` | 一个版本都没有 | 还没有生成任何版本 | 粘贴一份岗位描述，系统会按它生成一份可投递的简历。 | 去粘贴 JD |
| `no-diagnosis` | 还没发起过诊断 | 还没有诊断结果 | 诊断会指出这份简历缺什么、哪里不顺，并给出改写建议。 | 开始诊断 |
| `no-diagnosis-issues` | 诊断跑完但零意见 | 没有查出问题 | 这份简历暂时没有查出需要修改的地方，改过之后可以再诊断一次。 | 重新诊断 |
| `comments-filtered` | 有批注但被筛选条件挡住 | 当前条件下没有批注 | 批注还在，只是被筛选条件挡住了。 | 清除筛选 |
| `comments-ignored` | 批注全被标成了忽略 | 批注都被标成了忽略 | 这些批注都标了忽略所以没显示。清空诊断结果后重新诊断一次，就能再看到它们。 | （无） |
| `jd-no-requirements` | JD 里没提取到要求条目 | 没有提取到明确的要求条目 | 这段 JD 里没有能被认成岗位要求的句子。改一下写法，或者直接生成版本。 | 编辑 JD |
| `version-not-found` | 打开的版本 ID 不存在 | 没有找到这个版本 | 这个版本可能已经被删除了。 | 回到版本列表 |
| `no-diff` | 版本正文与当前简历一致 | 没有可对照的改动 | 版本正文和当前简历完全一致，所以没有差异可对照。 | （无） |
| `all-covered` | 这份 JD 没有未覆盖的要求 | 要求都能找到对应事实 | 这份 JD 的要求在你的简历中都有对应事实，不需要额外补充。 | （无） |

### 3.1 批注栏的三种空

「没诊断过」「诊断过但零意见」「有意见但当前条件下看不到」是三件不同的事，混成一句「没有符合条件的批注」会让用户以为诊断没跑过。所以批注栏分三种：

| 情形 | 用哪一条 | 依据 |
| --- | --- | --- |
| 还没诊断过 | `no-diagnosis` | `diagnosisState === 'none'` |
| 诊断过但零意见 | `no-diagnosis-issues` | `diagnosisState === 'empty'` |
| 有意见但看不到 | `comments-filtered` 或 `comments-ignored` | `visible.length === 0` 时再看筛选有没有生效 |

「还没诊断」那一条的按钮文案由页面给：诊断页就地发起诊断，编辑页是跳到诊断页去。其余两条用状态表里的文案。

### 3.2 正向的空结果

`no-diff` 与 `all-covered` 是**好结果**，不是缺东西。它们照样走三层结构，但不加动作——没有要纠正的事，也就没有该点的按钮。

## 4. 警告态

警告不是失败，是「没出错，但你最好看一眼」。数量之类的可变内容走 `{value}`。

| 键 | 什么时候出现 | 标题 | 说明 |
| --- | --- | --- | --- |
| `pdf-sparse` | PDF 能读到的文字很少 | 这份 PDF 能读到的文字很少 | 可能是扫描件或图片页。下面是读到的部分，请核对后再保存。 |
| `unrecognized-sections` | 有几段认不出属于哪个分区 | 这份简历有 {value} 段我们不确定属于哪个分区，放在「其它」里了 | 下面这几段没能归到教育、经历、项目、技能任何一个分区，可以在纸上直接改。 |
| `low-confidence` | 解析置信度低 | 结构识别不完整，请确认后再保存 | 这次解析没能认出全部分区标题，下面是按启发式推断的，可以在保存前直接在纸上改。 |
| `structure-issues` | 保存时查出结构问题 | 这份简历有 {value} 处结构问题 | 这些地方缺内容或时间对不上，可以在纸上直接改。 |

## 5. 不进这张表的东西

| 情况 | 为什么不进 |
| --- | --- |
| 成功提示（`简历已保存`、`版本已生成`） | 成功没有「下一步」的问题，也不属于失败或空态 |
| 引擎产出的业务内容 | 解析出来的分区名、诊断意见、覆盖说明是内容不是状态 |
| 逐字段的表单校验 | 那属于输入校验，不是状态 |
| 破坏性操作的确认文案 | 走 `ElMessageBox.confirm`，正文直接说后果，见 `ui-copy-voice.md` |

发布前（P5）逐条走一遍，每条都要能回答「用户看到这句之后知道该做什么吗」：

- [ ] 每条失败态都弹出了消息提示，提示里同时有状态与下一步
- [ ] 每条失败态在页面里也有告警，标题与说明分开两栏
- [ ] 每条空态都有标题与说明，标题与说明不是同一句话
- [ ] 每条空态有主动作时，按钮点了真的能改变这件事
- [ ] 每条空态没有主动作时，说明里讲清了为什么没有
- [ ] 批注栏的三种空分别出现，且说法互不相同
- [ ] `no-diff` 与 `all-covered` 看起来是好结果，不是故障
- [ ] PDF 的各类失败分别都试过（不是 PDF、太大、页数太多、有口令、损坏、读不出来、组件没加载起来、没有文字层），文案与出路对得上
- [ ] 全文搜一遍界面，看不到「底稿」与禁用词
